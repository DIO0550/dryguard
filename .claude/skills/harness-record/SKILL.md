# harness-record — マージ後の評価を 1 ファイル残す

マージ済みの PR 1 本につき、`harness/records/pr-<番号>.md` を 1 ファイル増やし、
**その記録だけを変える PR** を出すところまでを行う。

**このスキルが持つのは手順だけ。** 何を守るかは `harness/records/README.md`、
形式・層の語彙・分類の語彙は `harness/records/TEMPLATE.md` が持つ。**書き始める前に両方を読む。**
ここに規則を写さないのは、同じ規則が 2 箇所にあると片方だけ古くなるため
（`AGENTS.md`「規約の持ち場」の「再掲しない」と同じ理由）。

## やらないこと

- **`- 対策済:` の行を自分の判断で書かない。** `count.sh` はこの行を「ここから数え直す」の
  起点として読むので、介入していない回に書くと**再発数が 0 に戻る**。行の中身（分類・層）を
  決めるのは `harness-growth` だけ。**写すのは、記録する PR の本文の「## 記録へ写す行」の節が
  宣言した行だけ**（手順 3）。節が無ければ「規約への反映」には**無しとその理由**を書いて終える
- **集計（`count.sh`）と、規約・フック・スキルへの介入をしない。** それは `harness-growth` の
  管轄（README「数えるのと、規約やフックへ手を入れるのは別の回に行う」）。
  同じ指摘が何度目かに気づいても、記録にその事実を書くところで止める
- **過去の記録を書き換えない。** 判断が変わったら新しい記録に書く
  （例外は README「宛先の記録へ後から併記を足すのは、書き換えに当たらない」だけ）

## 手順

### 1. 対象の PR を決め、記録を作る対象かを確かめる

引数で PR 番号が渡されればそれ。無ければ `post-merge-review.sh` の促しに出た番号、
それも無ければ `origin/main` の直近のマージから引く。

```bash
git fetch --unshallow origin 2>/dev/null || git fetch origin main
git log --merges --format='%H %s' origin/main | grep "Merge pull request #<番号> "
```

**マージされていない PR は記録しない**（まだ指摘が付きうる）。次のどれかに当たれば、
記録は作らない / 形を変える。判定の根拠は README の該当節。

| 当たるもの | 扱い | README の節 |
|---|---|---|
| `harness/records/` 配下だけを変える PR | 記録を作らない。その回の指摘は**次に実装が入る PR の記録へ併記**する | 「記録だけの PR には記録を作らない」 |
| 除外表にある PR | 記録を作らない | 「記録を作らない対象」 |
| 指摘が既に別の記録に併記されている | 記録は作るが、指摘は併記先を指すだけにし `- 分類:` を置かない | 同上 |
| `harness/records/pr-<番号>.md` が既にある | 作らない（書き換えない） | 「書き方」 |

記録だけの PR かどうかは、差分のファイル名で機械的に決める
（1 行以上出れば、records 配下以外を変えている）。

```bash
git diff --name-only <マージコミット>^1 <マージコミット> | grep -v '^harness/records/'
```

### 2. 一次情報を集める

**記憶・前の記録・PR 本文の自己申告から転記しない。** README「推測で埋めない」と
`AGENTS.md`「記録・PR 本文に数値や主張を書く前に」が要求する出どころは次のとおり。

| 記録の欄 | 出どころ |
|---|---|
| マージ日 | PR の `merged_at` |
| 関連 Issue | PR 本文・コミットメッセージの `#<番号>`（`Closes` / `親:` など） |
| 差分規模 | `git diff --shortstat <マージコミット>^1 <マージコミット>`。ファイル数・追加行・削除行を**そのまま**写す |
| 指摘（レビュー） | PR のレビュー・レビューコメント（スレッドごと）・PR へのコメント。**返信で直したか・直さなかった理由**まで読む |
| 指摘（CI） | PR の各コミットのチェックの結果。失敗したものはログまで当たり、**どのコミットで落ちて、どのコミットで直ったか**を書く |
| 指摘（自己修正）・手戻り | 関連 Issue のコメント（計画・却下した案・実装中の判断）と、PR のコミット列 |
| `- 対策済:` の行 | PR 本文の「## 記録へ写す行」の節。**数や評価ではなく、介入した側の決定をそのまま写す** — 行の中身（分類・層）を決めるのは介入した側で、記録を書く側に一次情報が無い |
| 実行環境（フックの発火など） | 関連 Issue・PR 本文に**その回のセッションが書き残したもの**。無ければ「確かめられなかった」と書く |

GitHub は MCP の `pull_request_read`（`get` / `get_commits` / `get_reviews` /
`get_review_comments` / `get_comments` / `get_check_runs`）と `issue_read`（`get_comments`）で読む。
**`get_check_runs` が返すのは先端のコミットの分だけ**なので、途中のコミットで落ちて
直した CI は `actions_list`（ワークフローの実行の一覧）から引く。先端が緑なだけで
「CI の失敗 0 件」と書かない。

**記録だけの PR からの併記を拾う。** 前回の記録より後にマージされた、`harness/records/`
配下だけを変える PR があれば、そのレビュー・コメントも読む。指摘があれば、この記録に
**どの PR の回のものか**を書いて併記する（README「記録だけの PR には記録を作らない」）。

**フックの発火は記憶からしか取れないことがある。** 別のセッションで記録するなら、
Issue・PR 本文に書き残されたものだけを使い、無いものは埋めない
（`AGENTS.md`「実装を始める前に」の hook-canary の項：canary が通っただけでは
不発と断定しない）。

### 3. `TEMPLATE.md` の雛形から書く

`harness/records/pr-<番号>.md` に、`TEMPLATE.md` の「テンプレート」の節の中身を写して埋める。

- **指摘 1 件 = 1 ブロック。** 同じ形の指摘が 3 件あっても 3 ブロックにする
  （`count.sh` は `- 分類:` の行を 1 件として数える）
- **`分類` は `TEMPLATE.md`「分類の語彙」からだけ選ぶ。** どれにも当たらなければ `なし`。
  語彙を足すのは `harness-growth` の側
- **直さなかった指摘・再現しなかった指摘**は、欠陥でなければ分類を付けずに本文で触れる
  （`count.sh` が再発として数えないように）
- **指摘 0 件でも記録を残す。** 「## 指摘」に 0 件であることと、そう言える根拠
  （見たレビュー・CI の結果）を書く
- 「## 規約への反映」は**無しとその理由**（このスキルでは介入しないため）。ただし PR 本文に
  「## 記録へ写す行」の節があれば、その中の `- 対策済:` の行を**一字も変えずに**写す。
  介入の中身（置いた場所・上の層を採らなかった理由）は PR 本文・関連 Issue から書く

### 4. 書いた数を一次情報から出し直す

書き終えたら、数と主張を**一次情報から出し直して**突き合わせる。記録の正確さの指摘は
このリポジトリで最も再発している形（`AGENTS.md`「記録・PR 本文に数値や主張を書く前に」）。

```bash
git diff --shortstat <マージコミット>^1 <マージコミット>   # 差分規模
grep -c '^- 分類:' harness/records/pr-<番号>.md             # 指摘の件数（併記先を指すだけの指摘は数えない）
grep -n '^- 対策済:' harness/records/pr-<番号>.md           # PR 本文の「## 記録へ写す行」と同じ行だけ（節が無ければ 0 行）
grep -E '^- 対策済: `[^`]+` 層=(hook|skill|観点|rules) at pr-[0-9]+$' harness/records/pr-<番号>.md  # 上と同じ行数（count.sh が読める形か）
```

本文に「N 件」「M 巡」と書いたなら、ブロックの数・レビューの巡の数と一致するかも見る。

### 5. 記録だけの PR を出す

- 変えるのは `harness/records/` 配下だけにする（この PR 自身には記録が要らなくなる）
- PR 本文の行の頭に `差分規模: <ファイル数> ファイル / +<追加行> -<削除行>` を置く。
  CI（`.github/workflows/pr-body.yml`）が突き合わせる。push の前にローカルでも走らせる

```bash
bash harness/ci/pr-body-diff.sh <本文のファイル> origin/main HEAD
```

- 本文を書き直したら、同じコマンドを走らせ直す（`AGENTS.md`「出し直す時点を『push の後』に置かない」）
