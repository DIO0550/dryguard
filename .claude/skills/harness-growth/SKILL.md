# harness-growth — 再発数から介入の PR を出す

`harness/records/` の記録を `count.sh` で数え、**再発している分類 1 つ**について
ハーネスを改善する PR を出すところまでを行う。

**このスキルが持つのは手順と分岐の閾値だけ。** 数え方は `harness/records/README.md`
「数え方」と `count.sh` の冒頭、層の語彙・分類の語彙は `harness/records/TEMPLATE.md`、
層の強さの順は `AGENTS.md`「強制力の序列」が持つ。**着手する前に読む。**
ここに写さないのは、同じ規則が 2 箇所にあると片方だけ古くなるため
（`AGENTS.md`「規約の持ち場」の「再掲しない」と同じ理由）。

## やらないこと

- **記録（`harness/records/pr-<番号>.md`）を作らない。** それは `harness-record` の管轄。
  このスキルは既にある記録の集計から始める
- **`- 対策済:` の行を記録へ直接書かない。** 介入した PR の記録はマージの後にしか無いので、
  **介入の PR の本文で宣言し、`harness-record` がその PR を記録するときに写す**（手順 5）。
  宣言するのはこのスキルだけで、`harness-record` は宣言の無い行を書かない
- **過去の記録を書き換えない。** 分類を割っても、昇格させても、古い記録の `分類:` は
  そのまま残す（`README.md`「書き方」）
- **1 回の実行で介入する分類は 1 つ。** 2 つ扱うと、片方だけマージして片方を差し戻す
  ことができなくなる（`AGENTS.md`「タスクの分割」の「独立してマージできるか」）

## 手順

### 1. 数える前に、材料が揃っているかを確かめる

`count.sh` は**有る記録だけ**を数えるので、記録の欠けは再発数の過小評価として黙って出る。

```bash
git fetch --unshallow origin 2>/dev/null || git fetch origin main
```

- `README.md`「欠けの突き合わせ」のスクリプトを走らせる。**出力が 0 行でなければ止める。**
  欠けた記録は `harness-record` で先に埋める（このスキルでは作らない）
- **前回の介入が記録に入ったかを確かめる。** マージ済みの介入の PR（本文に
  「## 記録へ写す行」の節を持つ PR）ごとに、宣言した行が記録にあるかを grep する。
  無ければ起点が抜けて、その分類が「未介入」のまま数えられる（pr-145 指摘 8 の形）

```bash
grep -n '^- 対策済: .* at pr-<介入の PR の番号>$' harness/records/pr-*.md
```

### 2. 数える

```bash
bash harness/records/count.sh
```

列の意味は `count.sh` の冒頭のコメント。**判断は `再発` の列で行い、`通算` では行わない**
（通算は単調増加するので、介入が効いたかを表さない）。

### 3. 分類ごとに分岐する

上から順に見て、**最初に当たった行**で決める。

| 当たるもの | やること | 閾値の出どころ |
|---|---|---|
| `再発` が 2 未満 | 何もしない | `AGENTS.md`「規約の更新」の「2 回以上」 |
| 介入済みで、`再発` が 5 以上 | **語彙を割る**（手順 4-B） | このスキルが持つ（Issue #56「語彙の飽和」） |
| 介入済みで、`再発` が 2 以上 | **層を 1 つ上げる**（手順 4-A） | `AGENTS.md`「規約の更新」の「同じ層で再発したら層を 1 つ上げる」 |
| 未介入で、`再発` が 2 以上 | **初めて介入する**（手順 4-A） | 同上の「2 回以上」 |

`なし` はこの表で扱わない。`なし` は `対策済` を持たない（介入の起点が無い）ので、
**再発数が減らず、常にこの表の上位に残る**。`なし` は手順 4-C で別に扱う。

**扱う分類を 1 つ選ぶ。** 引数で分類が渡されればそれ（`なし` なら手順 4-C）。
無ければ、`なし` を除いて `再発` の多い順に上から見て、**介入の PR がまだ開いている分類を
飛ばした最初の 1 つ**。選んだものと、飛ばした候補とその理由を Issue に書く。

### 4-A. 層を決めて介入する

層の語彙と置き場所は `TEMPLATE.md`「層の語彙」。

- **初めての介入でも、強い層から検討する。** `hook` → `skill` → `観点` → `rules` の順に、
  その分類の指摘を落とせるかを見て、**最初に落とせる層**を採る。採らなかった上の層ごとに、
  なぜ落とせないかを PR 本文に書く（pr-209「それより上の層を採らなかった理由」の形）
- **層を上げるときは、前回の層より弱い層を採らない。** 前回が `rules` なら `観点` 以上。
  前回が既に `hook` なら、同じ層で検査を広げる（効く範囲の足りない理由を本文に書く）
- 介入する前に、**最後の介入より後の記録から、その分類のブロックを全部読む**。
  再発したブロックが前回の介入の射程に入っていたか（守れなかった）、入っていなかったか
  （射程が狭かった）で、上げる層の中身が変わる。読んだブロックの一覧を Issue に書く

### 4-B. 語彙を割る

介入後 5 件以上の再発は、**1 つのタグに別種の問題が畳まれている**サインとして扱う。

- 最後の介入より後のブロックを全部読み、**原因の性質**（直し方が違うか）で族に分ける。
  指摘の出どころ（レビュー / CI）や見つかったファイルでは割らない
- `TEMPLATE.md`「分類の語彙」に新しいタグを足し、**元のタグと新しいタグの両方に境界を書く**
  （`unverified-claim` / `claim-staleness` が「書いた時点で正しかったか」の 1 問で割れている形）。
  1 件の指摘が 2 つのタグに当たると `count.sh` の数が割れる
- **介入は新しいタグにだけ置く。** 元のタグに `対策済` を宣言すると、介入していない族まで
  再発数が 0 に戻る（pr-209「分類を割ったのは `対策済` を置けるようにするため」）
- 割るだけで介入しない回は作らない。割った族のうち再発の多いほうに、手順 4-A で介入する

### 4-C. `なし` から昇格させる

`分類: なし` が 10 件溜まったら語彙へ昇格させる（`TEMPLATE.md`「分類の語彙」の末尾）。
`なし` の件数は減らないので、**10 件は「読みに行く合図」として使い、昇格の根拠にはしない。**

- `なし` のブロックを読み、**同じ形が 2 件以上ある族**を探す。`TEMPLATE.md` の語彙の
  説明に既に「`分類: なし` から昇格」と出どころが書かれている族は、昇格済みなので除く
- 見つけた族のうち 1 つを、`TEMPLATE.md` に新しいタグとして足す。説明には
  **出どころの記録と指摘の番号**を書く（既存の昇格した語彙と同じ形）
- 昇格させた族にも手順 4-A で介入し、`対策済` を**新しいタグで**宣言する。
  **`なし` には宣言しない**（`なし` 全体には介入していない。pr-145 / pr-197 の形）

### 5. 介入の PR を出す

- **計画・却下した案・その理由は Issue に書く**（`AGENTS.md`「実装の進め方」）。
  Issue が無ければ立てる
- PR 本文の行の頭に `差分規模: <ファイル数> ファイル / +<追加行> -<削除行>` を置く
  （`.github/workflows/pr-body.yml` が突き合わせる）
- **PR を作ったら、番号が分かった時点で本文に次の節を足す。** `harness-record` が
  この PR を記録するとき、節の中の行をそのまま「規約への反映」に写す

```markdown
## 記録へ写す行

- 対策済: `<分類>` 層=<hook|skill|観点|rules> at pr-<この PR の番号>
```

- 節の中には `- 対策済:` の行だけを置く。**割った・昇格させた回は新しいタグの行だけ**
- 本文を書き直したら差分規模を出し直す（`AGENTS.md`「出し直す時点を『push の後』に置かない」）

```bash
bash harness/ci/pr-body-diff.sh <本文のファイル> origin/main HEAD
```
