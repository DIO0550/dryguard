## ゴールと結果

`Cargo.toml` が宣言する最低対応版 Rust 1.85 では未安定の let chains を、
評価順と分岐条件を保った入れ子の条件に置き換えた。最低版を引き上げず、
`rust-version` からツールチェーンを選んで `cargo check --locked --all-targets`
を実行する MSRV ジョブを追加した。修正後の MSRV ジョブは成功したが、
通常の CI の Java LSP テストは失敗が残ったままマージされている。

## 指摘

### 1. MSRV ジョブがランナー既定 Python の tomllib に依存していた

- 分類: `なし`
- 出どころ: [Copilot のレビュー](https://github.com/DIO0550/dryguard/pull/543#discussion_r4573500049)
- 内容: 初期コミット `d3b3687` は Python の版を指定せず、Python 3.11 以降の
  `tomllib` で TOML を読んでいた。ランナーの既定版によって動作しなくなる懸念が指摘された。
  `2ee6b24` で公式 `actions/setup-python` を使う Python 3.12 のセットアップを加え、
  アクションも v6.1.0 のコミット SHA に固定した。
  [返信](https://github.com/DIO0550/dryguard/pull/543#discussion_r4573522922)で検証結果を示し、
  スレッドを解決した。
- 既存ルール: なし。AGENTS.md「CI で使うアクション」はアクションの SHA 固定を定めるが、
  スクリプトが使う Python の版の選択は定めていなかった。
- 次にどう防ぐか: 今回は記録のみ。CI の補助スクリプトも、使う標準ライブラリに対応した
  ランタイムを明示して実行する。

### CI の失敗と確認範囲

以下は今回の差分の欠陥と確定していないため、分類タグを付けない。

- `d3b3687` の [Rust CI](https://github.com/DIO0550/dryguard/actions/runs/43590845112) は
  MSRV ジョブに成功し、通常ジョブの Java LSP テストで `Unreadable` / `UnreadableHover`
  により失敗した。
- `2ee6b24` の [Rust CI](https://github.com/DIO0550/dryguard/actions/runs/43595522118) も
  MSRV ジョブに成功した。Python 3.12.16 のセットアップと Rust 1.85.0 の選択をログで確認した。
  通常ジョブは Java LSP テストの `Unreadable` と jdtls 終了待ちのタイムアウトで失敗した。
- ベース `6f36733` の [CI](https://github.com/DIO0550/dryguard/actions/runs/43420946779) にも
  Java LSP の `Unreadable` / `UnreadableHover` がある。ただし constructor / instance method
  のテストはその実行では成功しており、失敗集合や内容が完全に一致するとは扱わない。
- 初回 CI の再実行要求は `Resource not accessible by integration` で拒否された。
  再実行が開始できなかったことは [Issue の記録](https://github.com/DIO0550/dryguard/issues/541#issuecomment-6876730371)
  に残っている。Python の追加は独立した MSRV ジョブ内で、通常ジョブを省略する変更はない。

## 手戻り

Copilot の指摘に応じ、Python のセットアップを追加した。シェルで独自に TOML を抽出する案は、
引用符やセクションの解釈を別途持つことになるため採らず、既存のパーサを維持した
（[判断の記録](https://github.com/DIO0550/dryguard/issues/541#issuecomment-6877326677)）。

コミットの `-F` 指定が実行環境のラッパーに拒否され、同じメッセージを `-m` で渡した。
この制約とローカル検証は [実装検証の記録](https://github.com/DIO0550/dryguard/issues/541#issuecomment-6876681506)
に残した。

## うまくいったこと

- 最低版を上げず、実コンパイラによる MSRV の回帰検査を追加できた。
- `pre-push` の fmt / Clippy / doc / test と、最低版でのコンパイルを独立に確認した。
  実 LSP サーバを使う ignored テストはローカルで未実行であることも明記した。
- Java LSP の失敗はベースのログとも比較し、失敗内容の違いを残した。

実行環境について、`echo hook-canary` は通過した。セッション開始時のチェックアウトに
canary の配線があることは確認したが、Claude Code の PreToolUse の動作は確認できていない。
Git フックの検査は手動実行だった
（[着手時の記録](https://github.com/DIO0550/dryguard/issues/541#issuecomment-6876648204)、
[実装検証の記録](https://github.com/DIO0550/dryguard/issues/541#issuecomment-6876681506)）。
