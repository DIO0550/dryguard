## ゴールと結果

Rust の impl 内メソッドについて、`Self` を対象型へ置き換え、レシーバ・impl の型変数・
境界を含む型シグネチャを比較できるようにした。直接囲む impl ヘッダーを Chunk から渡し、
同じ対象型の別 impl を宣言位置の違いだけで不一致にしない。
`self` / `&self` / `&mut self` の違いと明示的レシーバの型構造を保持し、
impl とメソッドの型変数は別の名前空間で正規化する。trait impl は実装トレイトも保持する。

関連型の選択が必要な `Self::Item` などは引き続き `SiteDependentSpelling` とし、
解決の拡張は #303 に分離した。const generics は読み取り不可、trait の既定メソッドの
Self は対象外とした。[実測・計画と分割判断](https://github.com/DIO0550/dryguard/issues/281#issuecomment-5977468055)
および [後続 Issue の登録](https://github.com/DIO0550/dryguard/issues/281#issuecomment-5977582052) に経緯が残っている。

## 手戻り

- 計画レビューの指摘はすべて採用した。Self の同一性を impl の宣言位置で表す案は、同じ型の別 impl が不一致になるため採らなかった。対象型への置換・型変数・境界は安全に解釈するための一単位とし、関連型の選択だけを後続へ分離した。
- 最初の Self / 明示的対象型比較テストは、追加引数の API が未実装というコンパイルエラーで Red を確認した。振る舞いの assert が失敗した Red とは区別する。実装後の Green は上記の計画検証に記録されている。
- [最終検証](https://github.com/DIO0550/dryguard/issues/281#issuecomment-5977594593) と当時のログによると、手動の native pre-push は fmt / clippy / 通常テスト成功（1413 passed、87 ignored）。Rust 実 LSP スイートも21件成功した。
- その後の全 LSP 直列実行では lib の8件が成功した後、既存の自リポジトリ索引テストが `ServerStillWorking` で失敗した（Rust は20件成功・1件失敗）。当該テストの単独再実行は成功し、中断後の scan / semantics も4件 / 54件成功した。一括実行そのものが成功したとは扱わず、失敗原因もこの結果だけでは断定しない。CI の LSP 成功は上表で別途確認した。
- Rust fixture 自体の `cargo check` も成功した。ローカルの実測は Rust / rust-analyzer 1.94.1 で、CI の rust-analyzer 固定版（2026-09-21）とは異なる。
- [着手時の記録](https://github.com/DIO0550/dryguard/issues/281#issuecomment-5977451980) によると実行環境は Codex Work Mode。Claude Code のセッション URL は提示されておらず推測しなかった。canary は通ったが、起動時の PreToolUse 配線の読み込みは確認できず、層3は未判定。CI の hooks テスト成功からセッション内の発火は推定しない。
