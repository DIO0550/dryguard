## 指摘

### 1. 行継続した文字列の中の閉じブレースを本体の終わりと誤検出する

- 分類: `なし`
- 出どころ: レビュー（Copilot）
- 内容: `find_closing_index` が `'` / `"` を行末で必ず `Code` へ戻していたため、
  TypeScript の行継続（行末の `\`）で複数行にまたがる文字列を追えていなかった。
  指した行によっては**誤った範囲がそのまま返る**（黙ってずれる）。
  再現テストを先に書いて実バグと確定させてから修正した
- 既存ルール: なし（`rules/architecture.md`「取れなかったシグナルを既定値で埋めない」の
  裏側にあたる「間違った値で成功させない」は、明文化されていない）
- 次にどう防ぐか: 今回は記録のみ。分類の語彙に該当が無い

### 2. `stage1` という命名が中身を伝えない

- 分類: `naming-mismatch`
- 出どころ: レビュー
- 内容: `stage1` はパイプライン上の位置しか言っておらず、何をするモジュールかを伝えない。
  この名前の出どころは `rules/architecture.md` の表そのものだった
- 既存ルール: rules/naming.md「内容を表さない汎用語を使わない」（`Manager` / `Helper` と
  同じ形だが、**段の番号は例として挙がっていなかった**）
- 次にどう防ぐか: ルール追記（実施済み）。`rules/architecture.md` に
  「モジュールは段の番号ではなく責務で呼ぶ」と、その理由・却下した候補を書いた

### 3. 切り出しがモジュール直下の関数になっていて、`Chunk` が持っていない

- 分類: `module-api`
- 出どころ: レビュー
- 内容: `Chunk::new` はモジュール外から呼べないため、**チャンクの唯一の作り方が
  チャンクの外にある**状態だった
- 既存ルール: rules/architecture.md「モジュールの公開 API」
- 次にどう防ぐか: 今回は記録のみ。既存ルールの適用漏れで、ルール自体に不足は無い

### 4. ファイルの読み込みを `pipeline` が組み立てていて、`Location` が持っていない

- 分類: `layer-dependency`
- 出どころ: レビュー
- 内容: `pipeline::chunk_at` が `fs::read_to_string(location.path())` を組み立てており、
  **位置を持つ型ではなく、位置を受け取る側が読み方を知っていた**
- 既存ルール: rules/coding.md「禁止事項」（I/O は `lsp` と入口の層のみ）。
  この規約があるため、指摘どおりに直すと規約違反になる状態だった
- 次にどう防ぐか: ルール追記（実施済み）。「I/O を持ってよい場所」を節に分け、
  `location` を**範囲付き**（自分が指すファイルを読むところまで）で加えた

### 5. 行番号が `NonZeroUsize` のままで、0 始まりとの変換の置き場所が無い

- 分類: `smart-constructor`
- 出どころ: レビュー
- 内容: `NonZeroUsize` は「0 でない」しか言えず、0 始まりのインデックスと 1 始まりの
  行番号の変換に置き場所が無かった。実際 `syntax` に private ヘルパーが 1 つ生えていた
- 既存ルール: rules/coding.md「生成時に検証し、不正な値を存在させない」。
  ただし**行番号は名指しで「標準の型を使う例」として書かれていた**ので、
  指摘どおりに直すと規約と食い違う状態だった
- 次にどう防ぐか: ルール修正（実施済み）。「標準を先に探す」は残し、
  足りなくなる条件（その型に置き場所が要る操作があるか）を足した

### 6. 統合テストのヘルパーで `expect` が clippy に落とされる

- 分類: `なし`
- 出どころ: 自己修正（`cargo clippy --all-targets -- -D warnings`）
- 内容: `clippy.toml` の `allow-expect-in-tests` は `#[test]` の関数と `#[cfg(test)]` の
  モジュールしか見ない。`tests/` 配下の**ヘルパー関数**は本番コードと同じ扱いになる
- 既存ルール: rules/testing.md「テスト内の unwrap / expect」（**統合テストの
  ヘルパー関数を含んでいない**）
- 次にどう防ぐか: 今回は記録のみ。`panic!` へ置き換えて理由をその場に書いた。
  次に統合テストを書く回で同じことが起きたら 2 回目になる
