## 手戻り

- **実装の前に 1 回止まった。** `pipeline` の Swift の腕に何を返すかを、Issue からは決められなかった。案 A / B / C を Issue に書いて止まり、Discord とプッシュ通知を送った
  - 止まっているあいだに Stop フックが「未コミットの変更がある」と促した。ビルドの通らない途中の状態だったので commit / push せず、変更を捨てた
  - 回答の後、`main` が e169f79 → 0ad9eb0 に進んでいたので、fast-forward してから依存を解決し直した（同じ 0.7.4）
- 計画の検証を受けて、テスト（指摘 6 / 7）・コメント（指摘 3〜5）・文書（指摘 2）を足した。実装の検証を受けて、テスト 3 件・doc・テストの並びと名前を直した（指摘 8〜11）。どちらも最初の push の前で、コミットを実装とテストと文書に分け直して 6 本にした
- `cargo fmt --check` は、コミットの前に手で走らせた初回に落ちた。長いテスト名の関数の折り返しと、`assert_eq!` の 1 行化の 2 箇所。`cargo fmt` で直してからコミットしたので、CI と git hooks の検査では落ちていない
- main（#432 Java）の取り込みで 11 ファイルが衝突した。並行して進んでいた Issue が同じ網羅 `match` に腕を足していたため

実行環境（Issue #397 のコメント・PR #431 の本文に、その回のセッションが書き残したもの）:

- `echo hook-canary` は、着手時・最初の push の前・取り込み後の push の前の 3 回とも、deny されずに通った
  - セッションは主作業ディレクトリ `/home/user`（リポジトリの外）で起動していた。起動時に dryguard の `.claude/settings.json` が読まれたかは確かめられない
  - `SessionStart` の `session-url-notice.sh` の出力もコンテキストに無かった
  - そのため「層 3 は判定できなかった」とした（不発とは断定していない）
- git hooks（層 2）:
  - コミットのたびに `pre-commit: fmt` が出た。`commit-msg` は指摘 17 で発火した
