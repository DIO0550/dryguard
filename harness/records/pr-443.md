## ゴールと結果

Issue #399 のゴールは、Swift の依存の宣言を TypeScript / Rust と同じ `ImportSet` に載せること。

- 達成した:
  - `ImportSet::from_tree` の `Grammar::Swift` の腕で `import_declaration` を集める（それまでは空集合を返し、`NoDeclarations` になっていた。#397 からの引き継ぎ）
  - `ModulePath::from_swift_import`: `.` を `/` にし、要素のバッククォートを外す。importer の位置からは解決しない
  - 読めない宣言は `UnreadableDeclaration { line }` にする（`import` の字句を含む ERROR・宣言の中の MISSING・宣言を閉じた行に続く ERROR。間のコメントは飛ばす）
  - Issue が挙げたテスト 3 種に加え、種類の指定・`@testable` / `@_exported`・綴りの書き方・`#if`・読めない宣言の形を足した。差分の `fn test_` の追加は 14
  - `rules/naming.md` の `import` / `specifier` / `module path` の行に Swift の形を足した（Issue の完了条件）
- Issue からずれた点（理由は Issue #399 のコメントにある）:
  - Issue 本文の tree-sitter-swift 0.7.3 は、`Cargo.lock` では 0.7.4 だった。構文木は 0.7.4 で確かめた
  - Issue の「`.` を `/` にして綴りのまま持つ」に、バッククォートを外すことを足した（`` `Foundation` `` と `Foundation` を同じ依存先にする）
  - 演算子の import（`import func Swift.+`）は tree-sitter-swift が構文エラーにするので、読めない宣言として測れない側に倒した（指摘 9）
