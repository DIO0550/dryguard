### 1. 交差型を可換と決めつけて並べ替え、単一化できない 2 つを重ねた

- 分類: `plan`
- 出どころ: レビュー（Codex P1）
- 内容: 初版の `TypeStructure::sorted` は、共用体と交差型の両方の相手を整列していた。
  **交差型が並べる呼べる型はオーバーロードの並びそのもの**で、TypeScript は書かれた順に
  突き合わせる。並べ替えると**単一化できない 2 つが重なる**（偽陽性）。

  指摘を受けて `tsc 5.9.3`（`pnpm-lock.yaml` が固定している版）で実測した。

  ```ts
  type Wide = (x: string | number) => string;
  type Narrow = (x: string) => number;
  declare const forward: Wide & Narrow;    // forward("s") は string
  declare const backward: Narrow & Wide;   // backward("s") は number
  ```

  同じやり方で共用体も測り、**どちらの順でも `string | number`** を返すことを見た。
  並べ替えを落とすのは交差型だけでよい。

  **どこで決めたかというと、Issue へ書いた実装計画のコメント。** 「交差型（`&`）は共用体と
  同じく可換なので、同じ並べ替えを掛けます（追加費用がほぼ無い）」と書いており、
  **可換かどうかを確かめずに計画へ入れ、そのまま実装した**。

- 既存ルール: rules/naming.md「`overload set` の並びを落とさない」
  （「TypeScript のオーバーロード解決は書かれた順に突き合わせて最初に合ったものを採るので、
  並べ替えると同じ呼び出しが別のシグネチャへ解決する」）。
  **ルールは在ったが、`overload declaration` の並びにだけ効くものとして読んでいた。**
- 次にどう防ぐか: 今回は `rules/naming.md` の同じ見出しへ、交差型の並びも同じ扱いである
  ことと、呼べる型を含む交差型だけ例外にしない理由を足した（下の「規約への反映」）。
  **`対策済` の行は書かない**（同上）。

**分類を `plan` にした理由。** 迷った候補は 2 つある。

| 候補 | 採らなかった理由 |
|---|---|
| `enum-omission-direction` | 「共用体と交差型を『可換な演算子』の 1 つの扱いにまとめた」は、安全な倒れ方が違う 2 つを同じ規則で扱った形で近い。ただし `sorted` は**許可リスト・拒否リストで書いた判定ではない**ので、rules/coding.md の見出しの射程から外れる |
| `なし` | 対応する規約が在る（上記）ので、規約の抜けではない |

**採ったのは `plan`（計画の誤り・不足）。** 誤りが入ったのは実装ではなく、
**確かめずに「可換」と決めた計画の側**で、コードはその計画どおりに書かれている。

### 4. 共用体の入れ子を均す段が計画に無かった

- 分類: `plan`
- 出どころ: 自己修正
- 内容: Issue へ書いた実装計画は「読む → 付け替える → 並べ替える」までで、
  **`|` の結合の仕方を均す段が無かった**。`A | (B | C)` と `(A | B) | C` は同じ型だが、
  **入れ子の深さは並びではない**ので並べ替えでは均せない。
  `Scalar | null`（`Scalar = string | number`）を開くと `(string | number) | null` になり、
  書き下した `string | number | null` と重ならないことに実装中の実測で気づいて足した
  （`flattened_union` / `flattened_intersection`）。

  **指摘 1 とは別の誤り。** 指摘 1 は「交差型は可換だ」という**誤った前提を計画へ入れた**形、
  こちらは**要る段が計画から抜けていた**形で、直し方も逆を向いている
  （前者は並べ替えをやめる、後者は均す段を足す）。

- 既存ルール: `AGENTS.md`「実装を始める前に」の「計画の入力を鵜呑みにしない」は
  **Issue が挙げた入力**についての決まりで、**自分で立てた計画の抜け**には触れていない。
  分類としては `plan`（計画の誤り・不足）の「不足」に当たる
- 次にどう防ぐか: 今回は記録のみ
