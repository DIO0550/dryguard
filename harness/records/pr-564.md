## ゴールと結果

Issue #492 のゴールは、Swift の文字列（`line_string_literal` / `multi_line_string_literal`）の**文字の部分の個数**
（`""` は 0 個、`"x"` は 1 個、`"a\nb"` は 3 個）で正規化トークン列が変わらないようにすること。
Issue が挙げた 2 つの懸念（補間を含む文字列が 1 つの綴りになる／文字の綴りを比べられなくなる）も含めて達成した。
文字列は `Literal(Text)` 1 つにし、補間の式（フィールド `interpolation`）だけを歩く。
`leaf_divergence` は文字列の綴りを、補間の区間を `\(…)` に綴り直したもので比べる。

ゴールからのずれ（スコープ外として別 Issue にしたもの）: TypeScript のテンプレートリテラルにも同じ形がある（#562）。
複数行の文字列の字下げの違いが葉の綴りの違いに出る（#563。既存の形）。

差分規模は、マージコミット `9f369ffcfe3b27fa65e27afd30a5a3981b1e409e` とその第 1 親の
`git diff --shortstat` から取り直した。

### 1. 計画が、補間の区間の中の空白・コメント・`,` を入力の形に挙げていなかった

- 分類: `plan-case-omission`
- 出どころ: 自己修正（計画の検証）
- 内容: 計画は、文字列の綴りの中の「補間の式（`interpolated_expression`）の範囲」を `…` に置き換えるとしていた。

### 3. 補間の中の構文エラー（`ERROR`）が列からも綴りからも消え、違うペアが `identical` になった

- 分類: `input-form-omission`
- 出どころ: 自己修正（実装の検証）
- 内容: tree-sitter-swift 0.7.4 は、`"\(rate b)"` の `b` を補間の式の外の `ERROR` にする。その `ERROR` は `is_extra()` が真になる。
  実装では、列は補間の式だけを歩き、綴りの区間判定は extras を「コメント」として通していた。そのため `b` が両方から消えた。
  `"\(rate b)"` と `"\(rate c)"` は差分前は `b ↔ c` だったが、`identical` に倒れた（偽の `EXTRACT-CANDIDATE` の側）。
  直した形は次のとおり。
  - 列: 文字列が `has_error()` なら子をすべて歩く（`walked_string_children_of`）
  - 綴り: 書かれたとおりに残し、区間判定でも `ERROR` をコメント扱いしない
  - 回帰テストを token と leaf_divergence に 1 本ずつ足した。列の側のフォールバックを壊すと token のテストが落ちることを確かめた

  計画の検証は `ERROR` が列から消えることを挙げていたが、「綴りに残るので安全」としていた。実装の extras の扱いで、その前提が崩れた
- 既存ルール: `implementation-flow` スキル `references/implementation-review.md`「シグナルと判定」の入力の形の項 / rules/coding.md「列挙で判定を組むときは、漏れの倒れる向きを選ぶ」
- 次にどう防ぐか: 今回は記録のみ
