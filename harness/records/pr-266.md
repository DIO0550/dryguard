## ゴールと結果

Issue #40 のゴール「Rust の型シグネチャ比較でトレイト境界を考慮する」のうち、**hover の綴りを読んで境界・`where` / inline の書き分け・ライフタイムを正規化して比べる**ところまでを達成した。

- 境界は「左辺の型と境界 1 つ」の組の集合で持ち、inline / `where`・`+` の並び・同じ左辺への述語の分け方を落とす（`syntax::rust_callable`）
- ライフタイムは `'static` を除いて落とすと決め、理由と却下した案を Issue と `rules/naming.md` に書いた
- **型名・トレイト名を宣言まで辿る部分は #263 に分割した。** そのためマージ後も、型名・トレイト名が比較に残るシグネチャ（Issue 本文の例 `T: Display` と `T: Serialize` を含む）は実行時には「測れない（`NoTracedRecord`）」になる。Issue の例が単一化不能に出るのは、辿った記録を渡す単体テストでだけ確かめている。分割の理由は [Issue #40 の計画コメント](https://github.com/DIO0550/dryguard/issues/40#issuecomment-5868698296)

## 指摘

### 1. `dyn A + B` を並べ替えると `dyn` の付く相手が替わった

- 分類: `なし`
- 出どころ: 自己修正（テストの初回実行）
- 内容: tree-sitter-rust は `dyn A + B` の `dyn` を先頭の `A` にだけ付けるので、`+` の並びを並べ替えると `Box<Send + dyn Fn ..>` のように `dyn` の付く相手が替わり、`test_from_spelling_auto_trait_order_in_dyn_is_dropped` が落ちた。`dyn` / `impl` を並び全体に掛ける形（`BoundedMembers`）へ直した。push 前に直っている
- 既存ルール: なし（構文木の形に依存する正規化の誤り）
- 次にどう防ぐか: 今回は記録のみ

### 2. 境界の側に書いた `for<'a>` を落としていなかった

- 分類: `なし`
- 出どころ: 自己修正（push 前の自己レビュー）
- 内容: 左辺に書いた `for<'a> F: Fn(..)` だけを扱い、境界の側に書いた `F: for<'a> Fn(..)` は `for < >` が綴りに残っていた。省略形と単一化不能に出る（偽陰性側）。テスト `test_from_spelling_higher_ranked_bound_on_the_right_is_the_same_as_elided` を足して Red を確かめてから、`higher_ranked_trait_bound` を型の綴りの側で扱うよう直した
- 既存ルール: なし
- 次にどう防ぐか: 今回は記録のみ

### 3. 公開関数の doc が private な関数へリンクしていた

- 分類: `なし`
- 出どころ: 自己修正（`cargo doc`）
- 内容: `rust_normalized_outcome_of`（`pub`）の doc が private な `single_outcome_of` へ intra-doc link を張り、`cargo doc --no-deps` が警告を出した。リンクを外して綴りだけにした。**`cargo doc` は CI でも git hooks でも走っておらず、base の時点で同じ種類の警告が他に出ている**ので、この形は検査では落ちない
- 既存ルール: なし
- 次にどう防ぐか: 今回は記録のみ
