# harness/records — マージ後の評価記録

マージされた PR 1 本につき `pr-<番号>.md` を 1 ファイル置く
（例外は「[記録だけの PR には記録を作らない](#記録だけの-pr-には記録を作らない)」と
「[記録を作らない対象](#記録を作らない対象)」）。

## 何のためにあるか

`AGENTS.md`「規約の更新」は「ルールに書かれていない指摘が **2 回以上**出たら
規約の抜けとして扱う」と定めている。ここはその**回数を数えるための材料**。
指摘がレビューコメントに散っている限り横断して数えられないので、
分類タグを付けた形でマージのたびに 1 ファイル残す。

## `.claude/` の下には置かない

記録はマージのたびに必ず 1 ファイル増えるが、`.claude/` 配下への書き込みは編集のたびに
承認を求められる。記録を残すこと自体が目的なのに、毎回そこで人の手を止めるのは割に合わない。
読み書きの頻度が高い成果物はリポジトリの通常のフォルダに置く。

## 数え方

```bash
bash harness/records/count.sh
```

分類ごとに「**最後の介入以降**の再発数」「通算」「介入後の記録の本数」「前回置いた層」を出す。

**通算ではなく再発で判断する。** 通算は単調増加するので、介入が効いたかどうかを表さない。
再発を数えられるのは、介入した回の記録に次の行が入っているため。

```markdown
- 対策済: `naming-mismatch` 層=rules at pr-42
```

集計から介入の PR を出すまでの手順は `harness-growth` スキル
（[`.claude/skills/harness-growth/SKILL.md`](../../.claude/skills/harness-growth/SKILL.md)）。
この行は介入の PR の本文で宣言され、`harness-record` がその PR の記録へ写す。

## 書き方

形式・層の語彙・分類の語彙は [`TEMPLATE.md`](TEMPLATE.md)。
対象の PR の決め方から記録だけの PR を出すまでの手順は `harness-record` スキル
（[`.claude/skills/harness-record/SKILL.md`](../../.claude/skills/harness-record/SKILL.md)）。

- 指摘 1 件 = 1 ブロック（まとめない）
- **指摘 0 件の回も記録を残す**（「順調だった」もデータ）
- **過去の記録は書き換えない。** 判断が変わったら新しい記録に書く
  （宛先の記録へ併記を後から足すのは当たらない。「[宛先の記録へ後から併記を足すのは、書き換えに当たらない](#宛先の記録へ後から併記を足すのは書き換えに当たらない)」）
- **推測で埋めない。** 実際のレビューコメント・CI の出力に当たる

## 記録だけの PR には記録を作らない

**この `harness/records/` 配下だけを変える PR は、それ自身の `pr-<番号>.md` を作らない。**
その回にレビュー指摘が付いたら、**次に実装が入る PR の記録へ併記する**
（どの PR の回のものかを書く。1 段ずれるので、書かないと出どころが辿れない）。

**Why**: 記録を入れる PR にも記録が要るとすると、**その PR にもまた記録が要る**。
実際 pr-107 を入れた回には 15 件の指摘が付いており、そこで記録を作れば同じことが次にも起きる。

**Why not（指摘 0 件の回で止める）**: 「0 件なら次は書かない」でも連鎖は止まるが、
**止まるかどうかが指摘の件数で決まる**ので、書き終えるまで分からない。
**範囲で決めるほうが、着手する前に予測できる。**

**Why not（記録だけの PR の指摘を捨てる）**: 上の 15 件は**どれも記録の正確さに関するもの**で、
コードの欠陥は 1 件も無い（数の引き継ぎ・同じ数を 2 箇所に書く・数える範囲の書き落とし・
対策の側で分類する、など複数の形に分かれる。内訳は `pr-110.md`）。
**規約の抜けを数える材料としてはむしろ濃い**ので、連鎖を止めるために捨てる必要は無い。

### 宛先の記録へ後から併記を足すのは、書き換えに当たらない

**併記が宛先の記録に入らないままマージされたら、宛先の記録の末尾に節を足して埋める。**
既存の節・ブロックには手を入れず、**後から足したこと**と、どの PR の回のものかを節の頭に書く
（`pr-124.md` の PR #123 の回の併記がこの形）。

**Why**: 「書き換えない」が守るのは、**その回に書いた評価と数**。末尾に足した節は
それを変えない。宛先以外の記録へ置くと、出どころと宛先が 2 段ずれて辿れなくなる。

## 記録を作らない対象

**次の PR は記録を作らず、欠けとしても数えない。** 突き合わせで出ても埋めなくてよい。

| PR | 理由 |
|---|---|
| #1 | devcontainer の設定だけを変えた回。記録の仕組みが入る前 |
| #66 | `harness/records/` の仕組みを持ち込んだ回そのもの。最初の記録は次の #67 から |

**仕組みが入った #66 より前、と範囲で決めている。** #66 より後の PR は、
上の「記録だけの PR」に当たらない限りすべて記録を作る。

**指摘が既に別の記録に併記されている PR も、記録は作る。** ただし指摘は併記先を指すだけにし、
`- 分類:` の行を置かない（置くと `count.sh` が同じ指摘を 2 回数える。`pr-114.md` が
`pr-117.md` の B1 / B2 を指しているのがこの形）。

**Why not（遡って書けないものも欠けとして数え続ける）**: 突き合わせが毎回同じ 2 件を出し、
次に数えた人が同じ判断をやり直すことになる。

### 欠けの突き合わせ

記録の要るマージ済み PR のうち、`pr-<番号>.md` が無いものを出す。**出力が 0 行なら欠けは無い。**
`git log` を遡るので、**shallow clone では過去のマージが見えず、欠けを見落とす**
（先に `git fetch --unshallow origin` する）。

```bash
excluded=" 1 66 "
for c in $(git log --merges --format=%H origin/main); do
  pr=$(git show -s --format=%s "$c" | sed -n 's/^Merge pull request #\([0-9]*\).*/\1/p')
  [ -z "$pr" ] && continue
  case "$excluded" in *" $pr "*) continue ;; esac
  [ -f "harness/records/pr-$pr.md" ] && continue
  outside=$(git diff --name-only "$c^1" "$c" | grep -cv '^harness/records/')
  [ "$outside" -gt 0 ] && echo "PR #$pr: 記録が要るのに無い（records 配下以外 $outside ファイル）"
done
```

## 記録は溜まり始めている

本数は `ls harness/records/pr-*.md | wc -l` で数える（**この README には書かない**。
マージのたびに増える数を 2 箇所に置くと、片方だけ古くなる）。

`AGENTS.md`「実装を始める前に」には、記録から **2 回以上出た指摘だけ**が上がっている。
**数えるのと、規約やフックへ手を入れるのは別の回に行う。** 記録を書く回は材料を残すところまで。
