## ゴールと結果

Issue #176 のゴール（`TypeSignature` が持つのを `Callable` ではなくチャンクの型を表す enum に
して、アクセサのシグナルが付くようにする）は**達成した**。

| 綴り | #175 まで | この PR |
|---|---|---|
| `(getter) Holder.value: string` | `AccessorSignature`（測れない） | `Normalized` / `Read(string)` |
| `(setter) Holder.value: string` | `AccessorSignature` | `Normalized` / `Written(string)` |
| `(getter) Holder.handler: (a: string) => void` | `AccessorSignature` | `Normalized` / `Read((a: string) => void)` |
| `(property) Holder.handler: (a: string) => void` | `Normalized` | 変わらず（対照） |

**Issue が「決める必要があること」に挙げた 2 点は、根拠を Issue へ書いたうえで自分で決めた。**

| 決めること | 決めた内容 | 根拠 |
|---|---|---|
| `TypeStructure` 単体の正規化の入口 | `syntax::type_structure` に `from_spelling` / `normalized` を `pub(crate)` で足し、`type_names` を `pub(crate)` へ上げる | 依存方向は `semantics → syntax` のまま。ステージをまたぐ移動でも再配置でもないので `AGENTS.md`「設計判断の確認」には当たらないと判断した |
| `Read` と `Written` を単一化可能と見なすか | 見なさない | 重ねる側は偽陽性・分ける側は偽陰性（`rules/coding.md`「列挙で判定を組むときは、漏れの倒れる向きを選ぶ」）。実測で、対で書かれた getter / setter も hover が `(property)` に畳まないことを確かめた |

**設計の前に実サーバで綴りを実測した。** `pnpm install --frozen-lockfile` で
typescript-language-server 6.0.0 が入る環境だったので、一時の probe テストで hover の綴りを
直接確かめてから `ChunkType` の形を決めた（`(setter)` にも**プロパティとしての型**が返り、
`(T) => void` ではないこと・同じメンバーに対で書いても `(property)` に畳まれないことが、
