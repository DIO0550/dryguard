## ゴールと結果

Issue #176 のゴール（`TypeSignature` が持つのを `Callable` ではなくチャンクの型を表す enum に
して、アクセサのシグナルが付くようにする）は**達成した**。

| 綴り | #175 まで | この PR |
|---|---|---|
| `(getter) Holder.value: string` | `AccessorSignature`（測れない） | `Normalized` / `Read(string)` |
| `(setter) Holder.value: string` | `AccessorSignature` | `Normalized` / `Written(string)` |
| `(getter) Holder.handler: (a: string) => void` | `AccessorSignature` | `Normalized` / `Read((a: string) => void)` |
| `(property) Holder.handler: (a: string) => void` | `Normalized` | 変わらず（対照） |

**Issue が「決める必要があること」に挙げた 2 点は、根拠を Issue へ書いたうえで自分で決めた。**

| 決めること | 決めた内容 | 根拠 |
|---|---|---|
| `TypeStructure` 単体の正規化の入口 | `syntax::type_structure` に `from_spelling` / `normalized` を `pub(crate)` で足し、`type_names` を `pub(crate)` へ上げる | 依存方向は `semantics → syntax` のまま。ステージをまたぐ移動でも再配置でもないので `AGENTS.md`「設計判断の確認」には当たらないと判断した |
| `Read` と `Written` を単一化可能と見なすか | 見なさない | 重ねる側は偽陽性・分ける側は偽陰性（`rules/coding.md`「列挙で判定を組むときは、漏れの倒れる向きを選ぶ」）。実測で、対で書かれた getter / setter も hover が `(property)` に畳まないことを確かめた |

**設計の前に実サーバで綴りを実測した。** `pnpm install --frozen-lockfile` で
typescript-language-server 6.0.0 が入る環境だったので、一時の probe テストで hover の綴りを
直接確かめてから `ChunkType` の形を決めた（`(setter)` にも**プロパティとしての型**が返り、
`(T) => void` ではないこと・同じメンバーに対で書いても `(property)` に畳まれないことが、
`Written` の中身と Read / Written を分ける根拠になっている）。

**この PR から新しい Issue を 2 本出した。** #180（場所に依存する綴り）と
#181（共用体の並びで正規化が変わる）で、どちらも判断が要るので判断待ちにしてある。

### 1. 推論された型名が綴りのまま比べられる（この PR では直さず #173 へ）

- 分類: `plan`
- 出どころ: レビュー（Codex 1 巡目 P1）
- 内容: 戻り値の注釈を省いたアクセサ（`get user() { … }`）は、hover が返す綴りの型名
  （`(getter) C.user: User`）が構文木のどこにも無い。`Chunk::type_references` は**書かれた
  注釈しか集めない**ので辿れず、宣言の場所が付かないまま綴りで比べられる。別ファイルの
  構造の違う `User` と単一化可能に出る（偽陽性）。
- **この PR が入れたものではないことを確かめた。** アクセサではなく**普通の関数**
  （注釈を省いた `currentUser`）2 つを別ディレクトリに置き、実サーバで比べると
  `type_signature = Unifiable`。`origin/main`（`ada5494`）を `git worktree` に出して
  同じ 2 ファイルを比べても**同じ結果**だった。
  **ただし、この穴に載るチャンクはこの PR で増えている。** 直す前はアクセサが
  `AccessorSignature` で止まっており、hover の綴りを比較へ持ち込んでいなかった。
  仕組みは既存、**載る入力は新しく露出した**、が正確な言い方になる。
- 既存ルール: `rules/architecture.md`「どこまでを「取れなかった」に数えるか」が
  **この形を射程に入れていない**（今の表は「**開けなかった**型名」で線を引いており、
  ここで起きているのは**そもそも尋ねていない**型名が残る形）。#173 が既にこの判断待ち
- 次にどう防ぐか: #173 へ再現を追記した。直すと**戻り値の注釈を省いた関数すべて**が
  「測れない」側へ動くので、実コーパスで影響を測ってから判断する（#173 の現時点の推し）

### 2. 場所に依存する綴り（`typeof localValue`）が綴りのまま比べられる（#180 へ）

- 分類: `plan`
- 出どころ: レビュー（Codex 1 巡目 P1）
- 内容: `get value(): typeof localValue` は、ファイルごとに別の `localValue` を指すのに
  綴りが同じ。値の名前は型名のノードにならないので集める対象に入らず、
  `TypeStructure::Spelled("typeof localValue")` のまま綴りで比べられる（偽陽性）。
- **この PR が入れたものではないことを確かめた。** 指摘 1 と同じ形で、**普通の関数**
  （`function currentValue(): typeof localValue`）2 つで再現し、`origin/main` の worktree でも
  同じ結果だった。**載る入力が増える点も指摘 1 と同じ。**
- **検出手段は既にあることも確かめた。** `syntax::type_spelling::names_only_types` が
  `typeof localValue` / `{ [key]: string }` / `import("./local").T` / `this` をすべて
  `Some(false)` で返す（`string` は `Some(true)`）。今この判定が使われているのは
  **差し込みの可否**（`is_site_independent`）だけで、比較の手前には無い
- 既存ルール: 指摘 1 と同じく `rules/architecture.md`「どこまでを「取れなかった」に数えるか」の
  射程外。**こちらは型名ですらない**ので、#173 の案 A（辿った記録が無い**型名**を測れないにする）
  のままでは掬えない
- 次にどう防ぐか: #180 に再現・検出手段・決めること（どこで見るか / 落とす先 / 実コーパスで
  どれくらい動くか）を書いた

### 3. 共用体の相手が型変数を宣言していると並びで正規化が変わる（#181 へ）

- 分類: `plan`
- 出どころ: レビュー（Codex 1 巡目 P2）
- 内容: 付け替えの番号はシグネチャ全体の通し番号で、**共用体を書いた順**に振られる。
  並べ替えは付け替えの後なので、`(<T>(x: T) => T) | (<U>(x: U) => U[])` とその逆順が
  別の構造として残る（偽陰性）。
- **この PR が入れたものではないことを確かめた。** テストヘルパーで
  `same_structure("(cb: (<T>(x: T) => T) | (<U>(x: U) => U[])) => void", …逆順…)` が `false`。
  **アクセサではなく呼べる型の引数で再現している**とおり、
  `Callable::normalized` / `renamed` / `sorted` / `TypeVariableScopes` はこの PR で
  1 行も変えていない（`git diff ada5494..HEAD -- src/syntax/type_structure.rs` で確認）
- 既存ルール: `rules/naming.md`「共用体は並べ替えてよい」が、**並べ替える前の付け替えまでは
  言っていない**。倒れる向きは偽陰性なので、`rules/coding.md`「列挙で判定を組むときは、
  漏れの倒れる向きを選ぶ」の安全側
- 次にどう防ぐか: #181 に再現と選択肢を書いた。直すなら「番号をシグネチャ全体の通し番号に
  している理由」（入れ子のスコープごとに振り直すと単一化できない 2 つを重ねる）と
  ぶつかるので、**どこまでを「独立」と見なすか**の線を先に引く必要がある

**3 件を `plan` にした理由と、根が 1 つであること。** 3 件とも
**「既存の正規化・比較の穴に、アクセサを同じ手順へ載せたことで新しい入力が載る」**形で、
