## ゴールと結果

Rust の型エイリアスを宣言から右辺へ展開し、`type Amount = u64` を使う関数と
`u64` を直接使う関数を単一化可能として比較できるようにした。
宣言 hover を解析し、型名の構文ノードだけへ差し込む。別ファイル・修飾パス・import rename
にも対応し、束縛された型変数・引数名・関連型名・識別子の部分文字列は置換しない。

展開するのは宣言側スコープに依存しないことを確認できる右辺だけ。
宣言ソースの位置と右辺を照合し、プリミティブ表記ごとの hover で shadowing を検査する。
確認できない場合は展開候補を取り除き、測定不能の理由を残す。
型・ライフタイム・const 引数の当てはめは #299、右辺に残る名前の宣言側スコープでの解決は
#300 に分離した。[計画と分割しなかった理由](https://github.com/DIO0550/dryguard/issues/280#issuecomment-5975476461)
および [後続 Issue の登録](https://github.com/DIO0550/dryguard/issues/280#issuecomment-5975578585) に判断が残っている。

## 手戻り

- プリミティブ表記の安全性確認は、構文だけの判断から使用側 `typeDefinition`、さらに宣言側のソース照合と hover へ変更した。前者の取りこぼしは指摘5・6に記録した。`definition` の有無で判断する案も、本物のプリミティブに rust-src の宣言位置が返るため採用しなかった。
- エイリアスと右辺の比較、および shadowing の回帰は、修正前に振る舞いのテストが失敗することを確認した。これらの意図した Red 自体は欠陥として数えない。最終レビューで追加のブロッカーが無かったことは上記の実行経緯に残っている。
- 当初 cargo / rust-analyzer が無く、隔離した Rust と LSP の実行環境を用意した。TS サーバは既存 lockfile の `pnpm install --frozen-lockfile` で導入し、依存ファイルは変更しなかった。
- コミット時はそのシェルの PATH に cargo が無く pre-commit がスキップされた。別コマンドでは PATH を明示して fmt / clippy / 通常テスト / 全 LSP テストを実行し、[公開時の記録](https://github.com/DIO0550/dryguard/issues/280#issuecomment-5975678829) に native pre-push の手動実行成功も残した。CI の成功は上表の実行・ジョブ・ステップから別途確認した。
- CLI の push は GitHub の認証情報が無く失敗したため、接続済み GitHub プラグインで公開した。同じ公開時の記録に、ローカルの検証済み tree と公開 tree の SHA 一致を確認した旨が残っている。
- [着手時の記録](https://github.com/DIO0550/dryguard/issues/280#issuecomment-5975465650) によるとセッション URL は取得できず、推測では記載しなかった。canary は通ったが、起動時の Claude Code hook 読み込みは確認できず層3は未判定。CI の hooks テスト成功からセッション内の発火を推定しない。

## うまくいったこと

- 実 rust-analyzer の反例で、構造体による shadowing と、別プリミティブへの alias / import rename を分けて検証し、不十分だった修正を公開前に差し替えた。
- 宣言ファイルを didOpen していない場合の hover も実測し、別ファイルを辿る前提を確認した。
- I/O は codebase、構文・位置照合は syntax、LSP 問い合わせは semantics に置き、確認に失敗した展開結果を残さない形を維持した。
- 独立した残タスクを #299 / #300 として切り出し、今回の対応範囲と未対応時の理由を文書・テストへ反映した。
