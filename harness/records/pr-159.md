## うまくいったこと

**計画の入力を鵜呑みにせず、着手前に 4 点の食い違いを見つけた**
（`AGENTS.md`「実装を始める前に」の 1 項目目が効いた回）。

| Issue 本文の記述 | 実際 |
|---|---|
| 「`.d.ts` はどうするか（**今も読めない**）」 | **読めており走査にも入っている**。`index.d.ts` の `extension()` は `"ts"` を返す |
| 「`Grammar::of_path` に断られ、**黙って飛ばされる**」 | `unopened_declaring_documents_of` が `UnreadableDeclaringDocument` として拾う。倒れる向きは偽陰性ではなく「測れない」 |
| 「倒れる向きは偽陰性」 | 同上 |
| （言及なし） | `extension()` は `foo.mts` と `foo.d.mts` を**区別できない**。`.mts` / `.cts` の実装ファイルも走査から抜けていた |

**確かめ方は `scan` を実行して出力を読む形にした**ので、`.d.ts` が対象に入っていることが
`対象 2 ファイル` の数で出た。コードを読むだけだと `extension()` の挙動を思い込みで通しかねない。

**assert が落ちうるかを確かめた**（`rules/testing.md`「迷ったら、その 1 件だけ実装を壊して
走らせる」）。`Grammar::of_path` から `"mts"` だけを外して `cargo test --lib` を走らせ、
`codebase::tests::test_typescript_paths_of_a_directory_returns_every_typescript_file_in_path_order`
ほかが落ちることを確認してから戻した。

**指摘 1 を実測で切り分けてから返した。** 「`.cts` サポートを名乗るのをやめる」という
選択肢が提示されていたが、`.cts` + ESM `import` が今も動くことを実測で示して却下し、
Issue のゴール（`.d.cts` を開ける）を落とさずに済んだ。
