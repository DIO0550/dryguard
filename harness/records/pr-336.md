## ゴールと結果

Issue #321 のゴールは、チャンクごとに作り直していた Rust の型名解決のキャッシュ（宣言側のソース・impl 候補の構文解析・trait ごとの implementation の応答）を compare / scan の 1 回分で共有すること。確認事項は次の 3 つだった。

- キャッシュの持ち主（`pipeline` が compare / scan ごとに作り、`ReferenceSources` と同じように渡す形か）
- 循環・深さに依存する結果はキャッシュしない既存の方針（`at_declaration`）との整合
- 実コーパスで、チャンクあたりの implementation の往復とファイルの読み込みが減ること

3 つとも達成した。

- `semantics::resolved_type::RustDeclarationCache` を足し、`asked_semantics_of` / `asked_scan_semantics_of` がセッションごとに 1 つ作る。展開中の連鎖（`active`）だけはチャンクごとに持つ
- implementation の応答のキャッシュは新規（今までは無かった）。キーは trait の宣言位置で、`Answered` だけを覚える。再帰しない終端（`terminals`）も共有に含めた
- 一時的な `eprintln` で、変更の前後を同じ `scan --lang rust` で数えた。dryguard `src`（`3f16be8`）は宣言の hover が 2079 → 250、ソースの読み込みが 44 → 4。indexmap 2.14.0 `src` は 1625 → 126 と 68 → 8。`tests/fixtures/rust-traced/src` では implementation が 12 → 6 になった。scan の出力は 3 つとも `diff` で一致した。実コーパス 2 つには完全修飾形の投影が無く、implementation の減り方はフィクスチャでしか測れていない

配列長の評価器のソースの共有は、評価器の引数が別で独立してマージできるので #335 に分けた。

レビューと CI:

- Copilot のレビュー 1 件（`8c2d821` に対して `0 open findings`）。レビュースレッドは 0 件。PR へのコメントは、こちらが投稿したテストケースの表の 1 件だけ
- CI はブランチの実行が 3 件（Rust・PR body・Copilot のレビューの実行）で、どれも `8c2d821` で成功。push は 1 回だけで、途中のコミットで落ちた実行は無い
