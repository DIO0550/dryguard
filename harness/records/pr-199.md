## ゴールと結果

**#187 のゴールは「出現ごとの出どころをどう持つか」を決めて塞ぐことで、Issue の推しは案 1
（戻り値の注釈の有無を `syntax` から運ぶ）だった。案 1 を採ったが、Issue が書いていた
「戻り値」では足りなかった。**

| ゴール | 結果 |
|---|---|
| 出どころの持ち方 | **案 1 を採用。** 案 2（位置つき）・案 3（同じ綴りが 2 回で測れない）は却下 |
| 運ぶ単位 | **「戻り値の注釈」ではなく `value type`（値の型）として立てた**（下記） |
| 実コーパスでいくら失うか | **2 件（0.4%）**（`Normalized` 316 → 314） |
| `rules/` 側の単位 | 「型名 1 つ」から「出現 1 つ」へ出し直した（`6f146a2`） |

### 「戻り値の注釈」では足りなかった

チャンクの宣言が注釈を省ける位置は**形ごとに違う**。setter は引数の型が hover の綴りになり、
コンストラクタは囲むクラスの宣言が綴りを書く。「戻り値の注釈が無ければ倒す」で書いていたら、
**注釈を書いてある setter と全コンストラクタがまとめて測れない側へ落ちていた**。
語彙として `value type` / `value type annotation` を立て、`rules/naming.md` に足した。

### 実コーパスで測った効き

rxjs 7.8.1 の `src`（尋ねた 517 チャンク）。`compare` と同じ経路を辿る一時プローブで、
変更前（`fd3fbd6`）と head（`c9bf00b`）を同じ手順で測った（プローブはコミットしていない）。

| | 変更前 | head |
|---|---|---|
| `Normalized` | 316 | **314** |
| `UntracedTypeName` | 40 | **42** |
| `UnopenedTypeName` | 122 | 122 |
| `UnreadableSignature` | 33 | 33 |
| `SiteDependentSpelling` | 5 | 5 |
| `NoTypeThere` | 1 | 1 |

チャンク単位で差分を取ると**動いたのはちょうど 2 チャンク**（`internal/Observable.ts:488` /
`internal/testing/TestScheduler.ts:134`）。倒れる向きは偽陰性。
