## ゴールと結果

Issue #220 のゴールは「`classification::signal::CalleeDomainOverlap` を足し、`classification` の
決定木と `report` の `--explain` に載せる」。#31 から引き取った「callHierarchy が使えなかったときに、
どのシグナルで出た判定なのかを読める形にする」も含む。**達成した。**

- `compare` / `scan` とも hover → references → callHierarchy の順に尋ね、呼び出し先ドメインの重なりを
  シグナルに重ねる。測れなかった理由は `CalleeDomainsOutcome` の理由ごとに text / JSON に出る
- Issue の「決めること」3 つ（import overlap との重ね方・閾値・自分のドメインを数えるか）と、
  オーナーのコメントで足された「lib / node_modules を落とすか」は、計画コメントで決めてから実装した

**ずれ**: 1 つ。出力イメージの `依存先ドメイン不一致 (billing::Invoice vs inventory::Stock)` は
**この形では出ていない**。呼び出し先はファイルのパスから数えたドメイン（ディレクトリ）で、
型の名前（`Invoice` / `Stock`）は持たない。出るのは `呼び出し先ドメインの重なり 0.00 (…/billing 1件 <->
…/inventory 1件)` の形。型の側は Issue #220 のスコープ外に「このシグナルが出てから別に立てる」と
書かれており、この回では立てていない。
