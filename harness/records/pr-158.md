### 1. 自分で作った絶対パスを URI にして、応答を読む関数で戻していた

- 分類: `なし`
- 出どころ: レビュー（Codex P1）
- 内容: `projectInfo` に渡すパスを `SourceDocument` の URI から `uri::path_of` で
  戻していた。`uri::path_of` は先頭要素がドライブ文字なら `UriPathError::DriveLetter` を
  返すので、**Windows の絶対パスから作った URI は必ずそこで落ちる**。Windows では
  全候補ペアで `projectInfo` を 1 度も組み立てられず、呼び出し元ドメインが `LspUnusable` に
  なっていた。`SourceDocument::new` は URI を作る前に `uri::absolute_path_of` で絶対パスを
  計算しており、**それを捨てていた**だけだった
- 既存ルール: **どれにも当たらない。** `uri::path_of` の制約は
  **サーバが返した綴りを読む側の都合**で、こちらが作った綴りを通す相手ではない。
  「作った値を、読み戻す側の関数で扱わない」に当たる分類が語彙に無い
- 次にどう防ぐか: 今回は記録のみ（`分類: なし` の材料として残す）
