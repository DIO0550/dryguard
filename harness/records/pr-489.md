### 1. 計画が、`workspace/synchronize` を握手の語の中に入れていた

- 出どころ: 自己修正（計画の検証）

## 手戻り

- 指摘 5 を直したテストの最初の台本は、`initialize` に答えてすぐ `exit` するものだった。`initialized` の書き込みが握手の中で `BrokenPipe` になり、正しく `ServerClosedDuringHandshake` が返ってテストが落ちた。1 秒居てから終わる台本に直した
- PR を出した後に、main へ #487（jdtls を起動する `ServerCommand::java()`）が入った。`rules/naming.md` と `src/pipeline.rs` がコンフリクトしたので、両方の内容を残して解消した（`5a9a66a`）。`ServerLanguage::Java` が増えて `synchronizes_index` の網羅 match が通らなくなったので、Java を送らない側に足した
- 実行環境: 着手時のセッションでは `echo hook-canary` が deny されずに通った。起動時のツリー（`4352f2b`）の `.claude/settings.json` の `PreToolUse` には `hook-canary.sh` が配線されていた（77 行目）ので、層 3 の `PreToolUse` フックは発火していない。コンフリクトを解消した回はコンテナを起動し直したセッションで、canary を走らせておらず、発火したかは確かめられなかった
