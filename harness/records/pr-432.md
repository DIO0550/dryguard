  - 直さず残した。Java のチャンクがまだ無いので、この答えが載るチャンクも無い
  - バリアントを足す案は採らなかった。届かない経路のために、`report` 側の `match` まで広がるため
  - 腕のコメントに「事実と違うが届かない」と書いた（コミット `6417050`）
  - 置き換えは #387 に申し送った
- 既存ルール: rules/architecture.md「取れなかったシグナルを既定値で埋めない」
- 次にどう防ぐか: 今回は記録のみ（#387 で置き換える）

実行環境（Issue #384 のコメント・PR #432 の本文に、その回のセッションが書き残したもの）:

- `echo hook-canary` は、着手時と push の前の 2 回とも、deny されずに通った。セッション起動時点のブランチ（HEAD `0ad9eb0`）の `.claude/settings.json` の `PreToolUse` には `hook-canary.sh` が配線されていた。配線はあったのに発火していないので、このセッションでは層 3 が発火していないと判断した
- git hooks（層 2）: 5 本のコミットそれぞれで `pre-commit: fmt` が出た。push の出力は末尾しか見ておらず、`pre-push:` の行が出たかは確かめられなかった。push 前の fmt / clippy / test は手で 1 つずつ走らせ、どれも exit 0
- `cargo test -- --ignored` はローカルでは走らせていない（typescript-language-server も rust-analyzer も無かった）。CI の Rust ワークフローが成功している
- `resolve.sh` を nightly 1.101.0 で走らせたところ、`flag -Z min-publish-age has been stabilized in the 1.100 release` と警告が出た。`AGENTS.md` / `harness/deps/README.md` の「stable では無言で無効」は、stable が 1.100 に上がった時点で古くなりうる。Issue #384 のコメントに書いた。この PR のスコープ外
