## ゴールと結果

引数のない Rust 型エイリアスの右辺を宣言ソースの位置から辿り、使用側の同名型や
型変数へ捕捉されずに比較できるようにした。具体型の宣言位置を比較用の識別子にし、
連鎖・再 export・入れ子の型と、プリミティブ表記の shadowing を実 LSP で確認した。
循環と展開上限は別の測定不能理由として text / JSON に出力する。

定数式を含む配列長の評価は #307 に分離した。未評価の定数式は綴りの一致だけで比較せず、
`UnopenableAlias` とする。自由な名前を含む generic エイリアスの対応範囲は広げず、
Self / impl のメソッドも今回の対象外にした。
[分割・計画と実測](https://github.com/DIO0550/dryguard/issues/300#issuecomment-5988750451)
に独立してマージできると判断した理由が残っている。

## 手戻り

- 計画レビューの指摘はすべて採用した。使用側で右辺を解決する案と、自由な型名を文字列のまま差し込む案は捕捉を防げないため却下した。無制限の再帰も採らず、宣言元での循環検出と深さ上限を置いた。
- [実装時の判断](https://github.com/DIO0550/dryguard/issues/300#issuecomment-5988890006)で、深さだけでは右辺が倍増する連鎖を抑えられないと判断し、64 KiB のサイズ上限を追加した。後の指摘5で構築前の検査へ変更した。
- `named_alias` と元の型の比較で既存の `UnopenableAlias` と期待する単一化可能の不一致を先に確認した。この意図した Red 自体は欠陥として数えない。
- ローカルの LSP 統合実行は途中の成功ログだけで全テスト群の完了行が無かった。再取得を試みた際に exec-server の `transport disconnected` が発生し、読み取りも復旧できなかった。ローカル全件成功とはせず、CI の完了結果を別途確認した。
- [着手時の記録](https://github.com/DIO0550/dryguard/issues/300#issuecomment-5988713211)と[公開後の補足](https://github.com/DIO0550/dryguard/issues/300#issuecomment-5991150365)によると実行環境は Codex。Claude Code の SessionStart URL は得られず、推測していない。`echo hook-canary` は通ったが、起動時の設定読み込みを確認できず、層3の発火は未判定。CI の hooks テスト成功からセッション内の発火を推定しない。
- GitHub 経由の公開では git hook は発火しないため、fmt / clippy / 通常テストを個別実行した。検証したローカル tree と公開 tree の一致も確認した。レビュー修正時はローカル環境が使え、本文の差分規模検査を公開前に実行した。

## うまくいったこと

- 宣言側と使用側の同名型・型変数・再 export・連鎖を対照テストにし、プリミティブ表記を shadow する直接使用との一致も確認した。
- 展開の深さ境界、終端キャッシュを先に温めた場合の順序、右辺のサイズ上限を別のテストで検証した。
- 独立した定数式評価を #307 に分離し、未評価の同名定数を同じものとして比較しない扱いを維持した。
- 計画・実装のレビューと Copilot の指摘を Issue / PR に残し、未確認のローカル実行結果と CI で確認した結果を分けた。
