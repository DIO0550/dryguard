## 手戻り

- Issue の疑問点で 1 度止まり、オーナーの回答（案 A）を待ってから計画に入った
- 指摘 1〜7 の修正。どれも push・PR 作成より前で、CI の失敗は無い
- push 前に `cargo test` を走らせ直すと、`tests/fail_on.rs` の 13 件が「CLI を起動できる」で落ちた。原因は、実装の検証のサブエージェントが scratchpad の一時 worktree で同じ target ディレクトリを使ってビルドしたこと。テストバイナリの `CARGO_BIN_EXE_dryguard` が、消えた worktree のパスを指したままになっていた。`cargo clean -p dryguard` で作り直すと 1774 passed / 0 failed / 111 ignored に戻った。成果物の欠陥ではないので指摘には数えない

実行環境（Issue #405 のコメントと PR 本文から転記）:

- `echo hook-canary` は、着手時と push の前のどちらでも deny されずに通った。セッションを起動したコミット（`bf584aa`）の `.claude/settings.json` の `PreToolUse` の `Bash` には `hook-canary.sh` が配線されていた、とセッションが確かめて書いている。層 3 は発火していない
- 層 3 が発火していないので、`plan-impact-check.sh` と `issue-comment-count-check.sh` も Issue コメントを検査していない。計画のコメントには `影響範囲の出どころ:` の行を置いた
- 層 2 は発火した。pre-commit（fmt / probe）がコミットごとに走り、push の出力にも pre-push のテスト結果の行が出た
- `cargo test -- --ignored` は走らせていない。typescript-language-server と sourcekit-lsp がこの環境に無かった（`which` で確認）
