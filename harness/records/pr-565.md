# PR #565 jdtls の callHierarchy が問い合わせのたびに始める作業で ServerStillWorking にならないようにする

- マージ日: 2026-11-23（`merged_at: 2026-11-23T07:12:59Z`、UTC）
- 関連 Issue: #504
- 差分規模: 6 ファイル / +326 -25

## ゴールと結果

jdtls 1.63.0 の callHierarchy は尋ねるたびに応答の前に作業（題 `Background task`）を始めて終えるので、
上限（32 回）まで尋ね直して `CalleesOutcome::ServerStillWorking` になっていた。これを、読み込みの後の
答え（`Answered` / `NoCallees`）を受け取れるようにするのがゴール。

Issue の「決めること（実装前に判断を仰ぐ）」に従い、選択肢を Issue に書いて一度止まった
（[判断を仰いだコメント](https://github.com/DIO0550/dryguard/issues/504#issuecomment-7091495708)）。
オーナーの返答「推奨でいいよ」で案 A（`ServerLanguage` から「問い合わせ自身が始める作業の題」
＝ `query progress` を渡し、その題で尋ねている間に始まって終わった作業を、答えを捨てる理由にしない）に決まった。

達成した。CI の先端 `cb0858e` の `fmt / clippy / test` ジョブの `cargo test (LSP)` ステップが成功しており、
`tests/java_lsp.rs` の `test_jdtls_answers_hover_references_and_callees`（`Answered` に `Total.java` を含む）が通った。
TypeScript / Rust / Swift の実サーバテストも同じステップで通っている。
「32 回尋ね続けない」は `Answered` が返ったことから言えるが、1 回目で採れたかは測っていない。

差分規模は、マージコミット `5ae71ba0965b23635f491615ca0da7eda5cb1694` と第 1 親の
`git diff --shortstat` から取り直した。
