## ゴールと結果

Issue #37 のゴール「Rust のソースに対して `scan` が動き、候補ペアが列挙される」は達成した。
自由関数・固有メソッド・トレイト実装メソッドをそれぞれ 1 チャンクにし、`use` を既存の
`ImportSet` に載せた。`scan --lang rust` と `auto` を追加し、TypeScript と Rust の間では
比較しない。Rust の Stage 2 はこの Issue の範囲外なので、意味シグナルは `NotAsked` とし、
TypeScript LSP へは送らない。`compare` でも異言語の組をエラーにし、Rust 同士では Stage 2 を
尋ねないことをテストした。

## 指摘

### 1. Rust の import パスが OS によって異なる値になりうる

- 分類: `smart-constructor`
- 出どころ: レビュー（[Copilot の指摘](https://github.com/DIO0550/dryguard/pull/254#discussion_r4113565006)）
- 内容: `ModulePath::from_rust_use` がソース根と importer のパスをそのまま文字列化しており、
  `ModulePath` の区切りを `/` にする不変条件を Windows で破りうる。両方を
  `with_forward_separators` に通し、Windows 形式のパスを含むテストを追加した
- 既存ルール: rules/coding.md「生成時に検証し、不正な値を存在させない」
- 次にどう防ぐか: 今回は記録のみ。新しい生成経路でも型の不変条件を確かめる

  `DifferentLanguages` は未検証だった。Rust と TypeScript のフィクスチャでエラーの変種、
