## ゴールと結果

Issue #318 のゴールは、候補 impl の型変数が使用側の具体的な型（型変数を含む部分型を含む）に当たる組でも impl を選び、RHS を展開すること。確認事項は次の 3 つだった。

- captures を「使用側の型変数」と「具体的な型」の 2 通りで持つ表現
- 部分型（`Holder<Vec<T>>`）の代入
- blanket impl を選んでよい条件

3 つとも達成した。

- `RustCapture`（`Variable` / `Concrete`）を足した。具体的な型は、使用側の impl の型変数を引数に取る `RustGenericAlias` のテンプレートで持つ
- 境界の無い blanket impl は選ぶ。境界・where 句を持つ候補（blanket を含む）は選ばない。境界を満たさない型には別の impl が共存できるので、coherence では 1 つに決まらず trait 解決が要るため。この結論は Issue #318 に書いた
- 計画の検証で、境界の無い impl にも暗黙の `Sized` があることが分かった（指摘 1）。そこで、具体的な型を当てはめる候補は implementation の impl を照合し終えたときだけ選び、型変数だけの一致を優先する規則（`UnselectedImpls::chosen_from`）を足した

既存の `concrete`（`impl Holder<u8>` の中の `<Self as Other<u16>>::Item`）は、`UnresolvedAssociatedType` から `Normalized` に変わった。
