# PR #575 compare のモジュール距離をパス表記に依存させない

- マージ日: 2026-11-28
- 関連 Issue: [#542](https://github.com/DIO0550/dryguard/issues/542)
- 差分規模: 5 ファイル / +244 -23

## ゴールと結果

`compare` で相対・絶対パスの混在や `..` の綴りだけで距離と判定が変わる問題を直す。
CLI の入口で距離計算用に両方の親ディレクトリを OS で解決し、測定は `syntax` に残した。
ソースの読み込み、ドメイン宣言、LSP、表示には元のパスを使う。ファイル名自体のリンクは辿らない。
CLI 回帰では同じディレクトリの距離 `0` と判定 `REVIEW`、別ディレクトリの距離 `2` と
`DO-NOT-EXTRACT` を確認した。[PR #575](https://github.com/DIO0550/dryguard/pull/575) の
[マージコミット](https://github.com/DIO0550/dryguard/commit/5f9b95bff880aed68e2cd605e56b2bd256f5e157) と第1親の `git diff --shortstat` で差分規模を確認した。

## 指摘

  `src/a.ts` からの距離は前者が `0`、後者が `2` だった。
  `6f93772` では両方の親ディレクトリを解決し、同じ距離 `2` と判定に揃えた。
  [回帰テストの結果を返信](https://github.com/DIO0550/dryguard/pull/575#discussion_r4724546015)し、スレッドを解決した。
- 既存ルール: `.claude/skills/implementation-flow/references/implementation-review.md`「シグナルと判定」
- 次にどう防ぐか: パス変換を変えるときは、直接指定と対応する別表記を並べ、
  途中のディレクトリのリンクと `..` の組合せも実ファイルで試す。今回は記録のみ。

## 手戻り

最初は距離用パスを絶対化し、`..` を字句上で畳んでいた。レビュー対応中、
`..` を含む側だけ親ディレクトリを解決すると、`src/jump/a.ts` と
`src/jump/child/../b.ts` で同じ親を別扱いすることも回帰テストで確認した。
片側だけの案を採らず、両側を同じ方法で解決する処理にした。読み込み・LSP・表示の経路は変えなかった。

PR 本文にあるとおり、`echo hook-canary` は通ったが Claude Code の層3の発火は確認できていない。
ローカルの `pre-push` は手動実行で、実 LSP を要する ignored テストはローカル未実行だった。

## うまくいったこと

修正前にリンク経由のテストが落ちることを確認し、修正後は直接指定・リンク経由の指定、
別ディレクトリの対照、公開 API の既存呼び出しをテストで残せた。
マージされた先端の [Rust CI](https://github.com/DIO0550/dryguard/actions/runs/46022918946) では、
最低対応 Rust、fmt / clippy / test、Claude Code hooks のテストが成功した。
