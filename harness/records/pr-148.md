# PR #148 開いた綴りを見る側も構文木に載せる

- マージ日: 2026-09-05
- 関連 Issue: #143
- 差分規模: 2 ファイル / +604 -212（コミット 4 本・マージを除く）

## ゴールと結果

Issue #143 のゴールは「**差し込む中身**（開いた綴り）と**正規化後の綴り**を見る側も、
PR #140 が置いた `syntax::type_spelling` の構文木に載せ替える」で、対象として
`declared_type_names_of` / `is_site_independent` / `Placeholders::renamed` の 3 つと、
落とす道具（`VETTED_MEMBER_MARKERS` / `QUOTE_MARKS` / `is_identifier_character` /
`identifiers_of`）が指定されていた。**達成した。**

`Placeholders::of` も同じ走査を使っていたので載せ替えの対象に入り、Issue が挙げていない
`VALUE_OPERATOR` / `TYPE_OPERATORS` / `BOOLEAN_LITERALS` / `names_a_declared_type` /
`Placeholders::push_renamed` も一緒に落ちた。`PREDEFINED_TYPES` だけは残した
（`bigint` が `type_identifier` として返るため。doc の「tree-sitter が `predefined_type`
として扱う一覧と同じもの」は実測と食い違っていたので直した）。

**Issue に無かった変更が 1 つ入った。** 入れ子の関数型を書き出すときの引数名
（`ParameterKind::marker` → `written_name`）。落とした名前のまま `?string` /
`...number[]` と書くと TypeScript の引数リストとして読めず、型名の位置を構文木で
決められない。載せ替えと同時でなければ既存の振る舞いを壊すので、同じ PR に入れた。

振る舞いの変更は 1 つだけ。文字列リテラル型のエイリアス（`type Mode = "on" | "off"`）が
開かれるようになった（Issue が「代償が消える」と書いていたもの）。

**レビュー指摘は 5 件、すべて Codex・すべて P2。** 人のレビューは付いていない。
Codex の Code Review は 4 巡走り、指摘が出たのは 3 巡（`0e8b586` で 1 件、`489a2d5` で
2 件、`cdaae0e` で 2 件、`0be6081` で 0 件）。CI（`fmt / clippy / test`）は 4 つの head
すべてで初回 success。テストは `main` の 596 件から 624 件になった（ignored 31 は変わらず）。

## 指摘

### 1. 差し替える側の一覧を数える側に流用し、外しすぎが偽陽性になった

- 分類: `なし`
- 出どころ: レビュー（Codex, P2, `0e8b586`）
- 内容: `bound_names_of` は**綴りごとに 1 つの集合**として束縛された名前の綴りを集め、
  同じ綴りのノードをすべて外す。`(<Local>() => Local) & Local` では外側の自由な `Local`
  まで外れる。差し替える側（`substituted_spelling_of`）ではこれで問題が無い（外しすぎても
  差し込みを見送るだけ = 偽陰性）が、**同じ一覧を `declared_type_names_of` にも使ったため
  倒れる向きが反転していた** —— 「辿る名前が残っていない」と答え、別々のモジュールの
  `Local` が単一化可能に出る（偽陽性）。範囲を 2 つに分けて直した
  （`substitutable_type_name_spans_of` / `type_name_spans_of`）
- 既存ルール: なし。`rules/architecture.md`「取れなかったシグナルを既定値で埋めない」は
  射程が近いが、あれは**シグナルが取れなかったとき**の話で、ここは
  **同じ一覧を用途の違う 2 箇所で使い回したとき、外しすぎの安全側が逆になる**話
- 次にどう防ぐか: 今回は記録のみ

### 2. 型述語を型 1 つ分として読もうとし、型ガードが丸ごと読めなくなった

- 分類: `なし`
- 出どころ: レビュー（Codex, P2, `489a2d5`）
- 内容: `function isUser(value: unknown): value is User` の戻り値は `value is User` で、
  これは**関数の戻り値の位置にしか書けない**。`type __ = value is User;` に包むと
  tree-sitter が `ERROR[value is]` を残す（実測）ので `substitutable_type_name_spans_of` が
  `None` を返し、**型ガードのシグネチャが丸ごと `UnreadableSignature` に落ちていた**。
  綴りを識別子で歩いていたときは読めていたので、この PR の回帰。包み方を 2 つ持たせて直した
  （型エイリアスの右辺 → 読めなければ `type __ = () => <綴り>;`）
- 既存ルール: なし。「載せ替える前が受け付けていた入力を、載せ替えた先でも受け付けるか
  確かめる」に当たる規約が無い
- 次にどう防ぐか: 今回は記録のみ

### 3. `typeof localValue` が site independent になっていた

- 分類: `なし`
- 出どころ: レビュー（Codex, P2, `489a2d5`）
- 内容: `localValue` は `type_query` の下の `identifier` で型名のノードにならず、指定子でも
  ないので `is_site_independent` が通していた。別々のモジュールがそれぞれの `localValue` を
  持っていると同じ綴りに開かれて単一化可能に出る（偽陽性）。綴りを識別子で歩いていたときは
  `localValue` を型名として数えていた（外れていたのは `TYPE_OPERATORS` の `typeof` だけ）
  ので、この PR の回帰。この巡では `holds_a_value_name` を 1 つ足して直した
- 既存ルール: なし（指摘 1 と同じ族）
- 次にどう防ぐか: 今回は記録のみ

### 4. オブジェクト型の計算されたキーが site independent になっていた

- 分類: `なし`
- 出どころ: レビュー（Codex, P2, `cdaae0e`）
- 内容: `{ [key]: string }` の `key` は `unique symbol` の値を指すが、
  `computed_property_name` の下の `identifier` で型名のノードにならない。`type_query` でも
  指定子でもないので、指摘 3 の修正を通り抜けた。`tsc --noEmit --strict` で
  （`declare const key: unique symbol` を添えて）有効な TypeScript であることを確かめている。
  綴りを識別子で歩いていたときは `key` を型名として数えていたので、この PR の回帰
- 既存ルール: なし（指摘 1 と同じ族）
- 次にどう防ぐか: 今回は記録のみ

### 5. `this` 型が site independent になっていた（到達経路は無い）

- 分類: `なし`
- 出どころ: レビュー（Codex, P2, `cdaae0e`）
- 内容: `this` は `this_type` になるので、指摘 3 / 4 と同じく素通りしていた。ただし
  **指摘が挙げた `type Self = this` は TypeScript として書けない**。`tsc --noEmit --strict`
  が `TS2526: A 'this' type is available only in a non-static member of a class or interface`
  を出し、クラス本体に `type` 宣言も書けない。`is_site_independent` が受け取る
  `ResolvedTypes` に入るのは型エイリアスの右辺だけ（`semantics::resolved_type` の doc）なので、
  **今の経路では届かない**。判定の穴としては同じ形なので閉じたが、到達しない状態を
  `semantics` 側のテストにはしていない（`names_only_types("this")` の単体テストのみ）
- 既存ルール: なし（指摘 1 と同じ族）
- 次にどう防ぐか: 今回は記録のみ

### 6. 計画の実測を、置き換える側の受け入れ範囲から逆算していなかった

  `(...number[]) => void` が読めないことを実測し、却下案に書いた。しかし
  `written_name` を古い印に戻す mutation を走らせたところ、**新しく足した 4 件だけでなく
  既存の 2 件も落ちた** —— `(string) => void`（省略可でも可変長でもない、素の必須引数）も

数える材料として、**`分類: なし` の 5 件（指摘 1〜5）は 1 つの族**である。

> **列挙で判定を組むとき、一覧から漏れた形がどちらへ倒れるかを見ていない。**

- 指摘 1 は、差し替える側では漏れが偽陰性（安全）になる一覧を、数える側へ流用して
  偽陽性に反転させた形

  漏れると偽陽性へ倒れる形。**文法が持つ形の数だけ指摘が続いた**
- 指摘 2 は向きが逆（漏れが偽陰性）だが、「載せ替える前が受け付けていた入力を
  数え上げていない」という点で同じところから出ている

最終的な修正は、**列挙する向きを反転**して漏れが偽陰性側へ倒れるようにしたもの
（`names_only_types`）。**1 巡目でこの問いを立てていれば、2 巡分の往復は要らなかった**
（手戻り 2）。

`plan` の 1 件（指摘 6）も、**「実測する対象を置き換える側から逆算していない」**という点で
上の族と同じところから出ている。ただし AGENTS.md「実装を始める前に」の項目に当たるので
`plan` を優先した（AGENTS.md「既存の `plan` に当たる指摘は、引き続き `plan` に分類する」）。
