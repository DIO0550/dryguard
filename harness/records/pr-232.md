# PR #232 dryguard.toml で閾値を外出しし、--threshold > toml > 既定値にする

- マージ日: 2026-09-23
- 関連 Issue: #35
- 差分規模: 21 ファイル / +968 -187

## ゴールと結果

Issue #35 のゴールは「ハードコードしてきた閾値を `dryguard.toml` へ外出しし、
`--threshold <0-1>` で上書きできるようにする」。**達成した。**

- `classification::ConfiguredThresholds`（新規・公開）が、外から動かせる 3 つを持つ
- `config`（新規）がカレントディレクトリの `dryguard.toml` の `[thresholds]` を読む
- 優先順位は `--threshold` > `dryguard.toml` > 既定値。`compare` を 3 通り走らせて実測した

**ずれ**: Issue は「外出しするのは実際に調整したくなった項目だけ」としか決めておらず、
どれがそれに当たるかは実装側で決めた。`harness/records/` を grep して根拠のある 3 つに絞り、
`SEPARATE_DIRECTORY_STEPS`（段数。0.0-1.0 の閾値ではない）と
`EXCLUDED_DIRECTORY_NAMES`（閾値ではない）は据え置いた。判断と根拠は Issue #35 に追記済み。

`shared_imports` / `shared_caller_domains` を外出しした直接の根拠は `pr-227.md` 指摘 2 で、
そこに「残る 2 つは**外から動かす手立てが無いので、互いの取り違えはこのテストでも落ちない**」
「**閾値の外出し（#35）が入れば同じ形で分けられる**」と書かれていた。
この回で 3 つを別々の値に動かすテストを足し、その穴を塞いだ。

## 指摘

### 1. `ConfigError::Unreadable` の経路にテストが無かった

- 分類: `test-coverage-gap`
- 出どころ: レビュー（Copilot、Medium、1 件のみ）
- 内容: `config` のテストは「ファイルが無い（`NotFound` → 既定値）」と「読めたが書式が違う」を
  固定していたが、**在るのに読めない**を固定していなかった。module doc は
  「無いことは正常。**読めなかったことと分けて扱う**」とこの分岐の Why を明示しているのに、
  それを守るテストが無く、`NotFound` の腕を広げる変更が入れば黙って戻る状態だった。
  `dryguard.toml` という名前の**ディレクトリ**をフィクスチャに置いて塞いだ
  （`chmod` を使わないのは、CI が root で走ると権限を外しても読めてしまうため）。
  `NotFound` の腕を全部の `Err` へ広げる mutation で**このテストだけが落ちる**ことを確かめてある。
- 既存ルール: rules/testing.md「振る舞いをテストする」/ rules/architecture.md
  「取れなかったシグナルを既定値で埋めない」（既定値へ落とさない分岐そのもの）
- 次にどう防ぐか: 今回は記録のみ。**実装側は規約どおりで、テストだけが追いついていなかった**。
  エラーのバリアントを足したらその経路のテストも足す、という形の規約は `rules/` に無い

## 手戻り

**`classification_of` の呼び出しを機械置換したとき、意図的に既定値と違う値を渡していた
テスト 1 件を潰しかけた。** `report` の
`test_scan_text_of_separates_the_pairs_it_lists_with_a_blank_line` は
「閾値を 0.0 まで下げて、比べたペアをすべて候補にする」ために
`Threshold::from_literal(0.0)` を渡しており、そこを `ConfiguredThresholds::default()` へ
一律に置換すると候補が 14 ペアから 1 ペアに減る。**コンパイラの `unused variable: threshold`
で気づいて**、`ConfiguredThresholds::default().with_structural_similarity(...)` として
下げた閾値を保ったまま移した。commit はしていない。

**指摘としては立てていない。** 置換していれば `assert_eq!(verdict_lines, 14)` が落ちるので、
**黙って通る形ではなかった**（`test-assert-weak` の定義に当たらない）。
機械置換の前に「その値が既定値かどうか」を見ていなかったのが原因で、
`rules/testing.md`「既定値と違う答えになる入力を選ぶ」が守ろうとしている入力を
機械置換の側から壊しかけた、という形。

**コミットを 3 本に分けるために `main.rs` の中間状態を作った。** 1 本目（閾値の配線）の時点では
`config` がまだ無いので、`configured_thresholds_of` が `--threshold` だけを重ねる形を一度書き、
2 本目で設定ファイルを読む形へ差し替えている。各コミットで `cargo clippy` と `cargo test` が
通ることは確かめた（1 本目の時点で lib 1068 passed）。

## うまくいったこと

- **疑わしい assert を 3 回とも実際に壊して確かめた**（`rules/testing.md`
  「迷ったら、その 1 件だけ実装を壊して走らせる」）。(1) `AppliedThresholds::of` が 3 つとも
  `structural_similarity` を入れる → `report` の新テストと `..._apart_from_the_others` が落ちる、
  (2) `WrittenThresholds::written` が `shared_imports` を別の枠へ書く → `config` の 4 件が落ちる、
  (3) `NotFound` の腕を全部の `Err` へ広げる → 指摘 1 で足したテストが落ちる。
  **3 つの閾値を既定値（どれも 0.5）とも互いとも違う 0.8 / 0.7 / 0.6 にした**ので、
  取り違えがテストに出る
- **`harness/records/` を grep して外出しの対象を決めた。** 「実際に調整したくなった項目だけ」という
  Issue の条件を、記憶ではなく記録から満たした。`pr-227.md` 指摘 2 が名指しで #35 を待っていたので、
  その穴を同じ回で塞げた
- **依存を 1 つも足さずに済ませた。** `toml` クレートは serde と proc macro を引き込むので、
  読む範囲を `[thresholds]` と 3 キーへ狭めて自前で読み、**知らない綴りはすべて `Err`** にした
  （漏れが「黙って既定値」へ倒れない向き）
