### 直さなかった指摘

欠陥ではないと判断したので、分類は付けない。

- auto のテストの `compared_pair_count() == 0` は、`chunk_count() == 1` から必ず出る（計画の検証・実装の検証の両方で出た）。名前も「集めない」に変えるよう提案された。だがオーナーが選んだ案 A は「Issue のテスト名のまま、今の振る舞いで書く」。`auto` が Swift を拾い始めたときにこのテストが落ちることが狙いなので、assert も名前も残した。今の時点で落ちうるのは `file_count` / `chunk_count` の 2 つ
- Rust 版のように `candidate_pairs().len() == 1` で「その 1 件だけ」を固定する（実装の検証）。1 つのフィクスチャに本番の組が 7 つあり、件数を固定すると類似度で決まる候補の数まで固定することになる。除外は `excluded_test_function_count() == 2` / `undersized_chunk_count() == 2` が支えている
- テスト名を `two_undersized_methods` などに変える（実装の検証）。Issue 本文が名前を指定しているので変えない
- `tests/scan.rs` の module doc が、入力を `tests/corpus/` だけと書いている（計画の検証）。Rust のフィクスチャのテストが入った時点で既に古く、この PR が古くしたものではない
- `Package.swift` を置く / `DiscountTests.swift` の `check(...)` が未定義（計画の検証）。Stage 1 は構文しか見ず、走査も `Package.swift` を読まない
