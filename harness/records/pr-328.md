# PR #328 feat: LSP サーバへの書き込みに受け取りの上限を設け、stdin を読まないサーバで止まらないようにする

- マージ日: 2026-10-10
- 関連 Issue: #319（`Refs`。項目 2 は判断待ちで、この PR では閉じていない）
- 差分規模: 4 ファイル / +412 -16

## ゴールと結果

Issue #319 の項目 1 は「stdin を読まないサーバに 64 KiB を超えるドキュメントを開かせても、有限時間で理由付きのエラーを返す」。これは達成した。

- 書き込みを別スレッド（`IntakeLimitedWriter`）へ出した
- 8 KiB の 1 塊が `intake` の期限（既定 120 秒）を超えて受け取られなければ、kill して `ClientError::ServerNotReading` を返す

項目 2（通知を流し続けるサーバへの合計時間の上限）は、この PR の範囲に入れていない。Issue が求めた大きなワークスペースでの実測（tokio）は、外部のコードのビルドスクリプトを実行するため、実行環境に拒否されてできなかった。dryguard 自身で測った値（冷えた状態で落ち着くまで 19.07 秒、1 回の待ちの最長 15.2 秒）を添えて、案 A / B / C を Issue に書き、判断待ちで止めた。

レビューと CI:

- Copilot のレビューが 1 件（`83b436e` に対して `0 open findings`）。レビュースレッドは 0 件。PR へのコメントは、テストケースの表を載せた自分のもの 1 件だけ
- push は 1 回（3 コミットをまとめて push した）。`actions_list` でこのブランチの実行を見ると、Rust・PR body・Copilot の 3 件とも `83b436e` に対して成功しており、途中で落ちた実行は無い

以下の指摘はすべて PR を出す前の自己修正で、出どころは計画の検証と実装の検証（どちらもサブエージェント）。採否は Issue #319 のコメントに残してある。

## 指摘

### 1. 書き込みのスレッドを作れなかったときのエラーを計画で決めていなかった

- 分類: `error-variant`
- 出どころ: 自己修正（計画の検証）
- 内容: 受け皿になりうる `OutputNotDrained` は「出力を読むスレッド」の文言なので、流用すると名前と実体が食い違う。`ClientError::InputNotForwarded` を足し、この経路でも kill と wait をしてから返す形にした
- 既存ルール: rules/coding.md「エラー型は原因ごとにバリアントを分ける」
- 次にどう防ぐか: 今回は記録のみ

### 2. 書き口の語彙が 3 通りに割れていた

- 分類: `naming-vocabulary`
- 出どころ: 自己修正（計画の検証）
- 内容: 期限のフィールドが `intake`、型が `StallLimitedWriter`、エラーが `ServerNotReading` と割れていた。`silence limit` ↔ `SilenceLimitedReader` ↔ `ServerUnresponsive` と同じ形にそろえ、`intake limit` ↔ `IntakeLimitedWriter` ↔ `ServerNotReading` にした
- 既存ルール: rules/naming.md「このツールの語彙を固定する」
- 次にどう防ぐか: 今回は記録のみ

### 3. 「64 KiB を超えれば止まる」をページサイズを確かめずに前提にしていた

- 既存ルール: なし
- 次にどう防ぐか: 今回は記録のみ

### 4. Client 側に足す予定の見限りの enum を、どのテストでも落とせなかった

- 既存ルール: rules/testing.md「assert は『落ちうるか』で見る」

## 手戻り

- 計画の検証の後に、2 つを変えた。どちらもレビューの巡ではなく、PR を出す前の変更
  - 語彙を `Stall` から `Intake` に変えた（指摘 2）
  - Client 側に足す予定だった enum をやめた（指摘 4）
- `cargo fmt --check` が、push の前のローカルの検査で落ちた（テスト名が長すぎて改行された）。テスト名を短くして `cargo fmt` をかけ直した。CI と git hooks では落ちていないので、`fmt-failure` には数えない
- 最初の `echo hook-canary` は、`cd ... && git status && ... && echo hook-canary` と連ねて走らせていた。`hook-canary.sh` はコマンド全体が `echo hook-canary` のときだけ当てるので、この 1 回は判定に使えない。単独で走らせ直した
- `cargo test -- --ignored` を走らせた副産物として、`tests/fixtures/rust-test-references/Cargo.lock` が生成された。コミットせずに削除した
