## ゴールと結果

Issue #237 のゴールは「#36 で決めた記法（`[domains]` にパスの glob を並べ、宣言がディレクトリからの
推定に勝つ）を実装する」。**達成した。**

- `config` が `[domains]` を読み、新しい `domain_declaration` がパスを宣言へ当てる。glob は `**` と `*`
  だけを自前で持ち、それ以外の書き方は書式の誤りとして止まる
- 宣言はモジュール距離・呼び出し元ドメイン・呼び出し先ドメインの 3 つに効く。名前の違う 2 つの宣言に
  当たるファイルは、比べるファイルなら判定の前に `Err`、参照元・呼び出し先なら「測れない」
- Issue の「実装のときに決めること」3 つ（glob の照合・文字列の配列の読み方・モジュール距離の
  シグナルの形）は、計画コメントで決めてから実装した

**ずれ**: 2 つ。どちらも着手時に止めてオーナーの判断（案 A）を得たうえでのずれ。

1. **宣言を当てる相手に呼び出し先を足した。** Issue は「呼び出し先は判定に入っていない」を前提に
   「モジュール距離・呼び出し元の両方」と決めていたが、#36 の後の PR #240（#220）で呼び出し先が
   決定木に入っていた（下の指摘 1）
2. **完了条件の 1 つ目を置き換えた。** 「#36 で出した『正解で出し直したラベル』と一致する」は、
   #36 の値が呼び出し先の入る前のもので突き合わせる相手が無い。`probe.sh` の決定木の写しを
   呼び出し先込みに直し、**宣言付きの `scan` と正解で出し直した判定を候補ペアごとに突き合わせ、
   食い違えば終了コード 1** にする形へ置き換えた。layered（突き合わせた 6 ペアで食い違い 0、
   引き直せなかった 17 ペアも同じ判定）・nested（63 ペアで食い違い 0）

完了条件の 2 つ目（宣言が無ければ判定が変わらない）は、`tests/scan.rs` の固定値に加えて、
main のバイナリとの `scan --format json` の突き合わせ（4 コーパスで候補ペアと判定が一致）で確かめた。
