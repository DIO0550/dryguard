## ゴールと結果

Swift の `X.Type` は基底型 `X` の宣言を辿り、メタタイプの構造を残して比較するようになった。
sourcekit-lsp が definition に宣言の場所を返さない場合、`--explain` は Swift 向けの説明を出す。
JSON の理由コードは `no-definition-site` を使う。[Issue #557](https://github.com/DIO0550/dryguard/issues/557)

`Int.Type` は同じ型のエイリアスと単一化でき、値の型 `Int` とは区別できた。
`AnyClass` は基底の `AnyObject` まで辿る。生成されたインタフェースではそのエイリアスの右辺が省かれるため
`UnopenableAlias` になる。[Swift 実サーバテストのログ](https://github.com/DIO0550/dryguard/actions/runs/45646105700/job/139317415644) [Issue #556](https://github.com/DIO0550/dryguard/issues/556)

差分規模はマージコミット `c098e47` と第1親の `git diff --shortstat` で確認した。
[マージコミット](https://github.com/DIO0550/dryguard/commit/c098e47a44712cc05b1d98eb67ac90ec5a0be6e1)

## 手戻り

レビュー対応中に `typealias Meta<T> = T.Type` を調べたところ、Swift 6.4.2 では `Meta<P>` が
`P.Protocol` と一致し、`P.Type` とは別の型だった。宣言位置だけで基底の種類を判定できない代入は
`UnopenableAlias` とし、配列や明示的な `any P` の代入は比較できるようにした。
[追加検証](https://github.com/DIO0550/dryguard/issues/557#issuecomment-7166941449)
