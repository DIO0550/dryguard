## ゴールと結果

Issue #26 のゴールは「typescript-language-server を起動し、**候補ペアが含まれるファイルだけ**を
`didOpen` して問い合わせに応えられる状態にする」。**土台までで、ゴールそのものには届いていない。**

**開かせる手段はできたが、どのステージからも呼んでいない。** `src/lib.rs` が
「まだどのステージからも呼ばれていない」と書いているとおりで、`main.rs` の `compare` /
`scan` の経路にも `Session::open_document` は現れない（呼んでいるのはテストだけ）。
**「候補ペアのファイルだけ」を守っているのも呼ぶ側**で、`open_document` は渡された
`SourceDocument` を開くだけなので、API 自体はその条件を強制しない。配線しなかったのは
意図した判断（シグナルの使い道が無い段階で繋ぐと LSP 無しで `compare` / `scan` が動かなくなる）
だが、**「達成した」と書くと配線まで済んだように読める。**

| Issue「やること」 | 結果 |
|---|---|
| サーバのプロセス起動（実行ファイルの探索・エラーメッセージ） | **既に入っていた**（PR #107 の `ClientError::ServerNotFound` / `Spawn` / `ServerClosedDuringHandshake`）。この回で足したものは無い |
| ワークスペースのルートを決めて `initialize` に渡す | `WorkspaceRoot::enclosing`（開かせるファイル群の共通の祖先）+ `rootUri` |
| 候補ペアのファイルを `textDocument/didOpen` で開く | `Session::open_document`。同じ URI への 2 通目は送らない |
| 使い終わったら `didClose` / `shutdown` する | `Session::close_document`（`shutdown` は既存） |

**完了条件は満たしていない。** Issue の完了条件は「候補ペアのファイルを開いた状態で、
**次の issue の** `hover` が応答を返す」で、hover は #27 の担当。`didOpen` / `didClose` は
通知で応答が返らないため、**hover が無い時点では開いた効果を外から観測できない**。
確かめたのは (1) 送る payload（フェイクのストリーム）と (2) 実サーバで起動 → 握手 →
`didOpen` → `didClose` → 正常終了までが通ること、の 2 つ。**この線引きは PR 本文と
Issue #26 に書いて出したが、承認された記録は無い**（レビューは自動レビューのみ）。

パイプラインへは配線していない（シグナルの使い道が無い段階で繋ぐと、LSP サーバが無い環境で
`compare` / `scan` が動かなくなる）。**Issue に書いたスコープ外の宣言どおり。**

### 1. Windows の verbatim 前置きをそのまま URI に置いた

- 分類: `test-coverage-gap`
- 出どころ: レビュー（Codex P1）
- 内容: `Component::Prefix` の綴りを `as_os_str()` のまま URI に足していたため、
  `\\?\C:` の形が来ると `file:///\\?\C:/...` になり、`\` と `?` が混じって URI として読めない。
  **Windows では 1 つもドキュメントを開けない状態だった。**
  `0b031b9` で、前置きの種類からドライブ文字だけを取り出す形に直した。
  **書いた分岐にテストが 1 つも無かった**のが素通りした理由で、
  Linux では `Path::components` が `Prefix` を返さないため `file_uri_of` 経由では届かない。
- 既存ルール: rules/testing.md「振る舞いをテストする」（差分の中心がテストから参照されていない）。
  **ただし「テストで駆動できない分岐をどう扱うか」は規約に無い。**
  rules/testing.md「LSP を要するテストは、飛ばしたことが分かる形にする」が近いが、
  あちらは `#[ignore]` で走らせられる話で、こちらは**この OS では原理的に到達できない**
- 次にどう防ぐか: **今回は記録のみ。** 直しでは、値を直接渡せる関数（`disk_letter_of`）に
  切り出してそこだけテストした。振る舞いのテストという原則からは外れる形なので、
  同種が再発したら「プラットフォーム依存の分岐の書き方」を rules に置くことを検討する
