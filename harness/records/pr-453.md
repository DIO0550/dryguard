## ゴールと結果

Issue #388 のゴールは、正規化トークン列が完全に一致する Java のチャンク 2 つで、束縛した名前の一貫した付け替えと、シグネチャに書かれた型を葉の綴りの違いに数えないこと。

- 達成した:
  - `java_binders_of` で Java の束縛を集め、`signature_type_nodes_of` / `parameter_type_nodes_of` で引数・戻り値・`throws` の型を外した
  - Java のメソッド名・注釈の要素名・メソッド参照の `::` より後ろを、束縛と同じ綴りでも外の名前として比べる（`OUTSIDE_NAME_FIELDS` と `is_outside_name`）

  - 完了条件の `rules/naming.md` の束縛の説明と、`bound_names_of` の doc（「TypeScript と Rust の両方に書く」）を出し直した
- Issue からずれた点（理由は Issue #388 のコメントにある）:
  - Issue の表は `try` のリソースを `variable_declarator`、`instanceof Foo f` を `type_pattern` としていた。tree-sitter-java 0.23.5 の構文木では、それぞれ `resource` の `name` と `instanceof_expression` の `name` だった

  - `README.md` の Java の「まだ無いもの」から葉の綴りの違いを外し、`docs/dryguard-plan.md` の表に `OUTSIDE_NAME_FIELDS` を足した（Issue の変更するファイルに無かった）
  - Java の型シグネチャは #395 まで `NoSignatureReader` で傾かないので、型だけが違う同じドメインの Java のペアは `compare` で REVIEW から EXTRACT-CANDIDATE へ動く。計画の検証で出た指摘で、計画を変えずに理由を Issue と PR 本文に残した（下の「直さなかった指摘」）
