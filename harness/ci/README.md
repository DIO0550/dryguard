# harness/ci — CI（層 1）が走らせる検査

`.github/workflows/` から呼ばれるスクリプトを置く。**ローカルでも同じものを走らせられる形**に
してあるので、CI に押し込んで初めて結果が分かる状態にはならない。

| スクリプト | 何を落とすか | 呼ぶワークフロー |
| --- | --- | --- |
| `pr-body-diff.sh` | PR 本文が宣言した差分規模と、実際の差分の食い違い | `.github/workflows/pr-body.yml` |
| `pr-body-diff-test.sh` | 上のスクリプト自身の壊れ | 同上（検査の前に走らせる） |

## 本文に置く宣言

行の頭から書く。箇条書きの `- ` と太字の `**` は付いていてよい。

```
差分規模: 6 ファイル / +338 -8
```

**行の頭に限るのは、本文が書式そのものを説明することがあるため。** 表のセルに書いた例まで
宣言として数えると、**書式を説明した PR が自分の例で落ちる**（この検査を入れた PR #209 が
実際にそうなった）。

**2 行以上あってもよいが、数は揃える。** 同じ宣言を 2 度書くのは害が無く、
食い違う 2 行はどちらかが実際と合わないので落ちる。

## なぜ CI（層 1）に置くか

**`AGENTS.md`「記録・PR 本文に数値や主張を書く前に」への介入が、層 4 では止まらなかったため。**

層 4（`AGENTS.md` の項目）は PR #145 で入っているが、その後 9 件再発している
（`harness/records/TEMPLATE.md` の `claim-staleness` が内訳を持つ）。
`AGENTS.md`「規約の更新」の「**同じ層で再発したら層を 1 つ上げる**」に従って上げた先がここ。

**層 2（git hooks）は使えない。** push の時点では PR がまだ無く、本文も存在しない。
この 1 件に限っては、**層 1 のほうが層 2 より早く効く**（Issue #153）。

## 何を覆っていないか

**覆うのは差分規模だけ。** 再発した 9 件のうち、この検査が落とせるのは 3 件
（`pr-194.md` 指摘 5 / 6 / 8）。残りは**本文にしか無い数や文言**で、
リポジトリから出し直せない。

| 再発した中身 | ここで落とせるか |
| --- | --- |
| 差分規模（ファイル数 / 追加 / 削除） | **落とせる** |
| 変異・記録の件数 | 落とせない（何を数えたかは本文にしか無い） |
| 引用した文言・綴り | 落とせない |
| 主張の条件（範囲の拡大） | 落とせない |

**落とせない分を落とせるふりをしない。** そこは `AGENTS.md` の
「出し直す時点を『push の後』に置かない」が層 4 のまま持つ。

## `edited` でも走らせる

再発した回はどれも「push した後に本文を直す」順序で、**push の時点の本文は必ず古い**。
`pull_request` の `edited` を含めてあるので、**本文を直した時点で検査が走り直す**。
push で赤くなり、本文を直すと緑になる。
