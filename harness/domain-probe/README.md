# ドメイン推定の外れ方を数える足場

Issue #36（`dryguard.toml` でのドメイン宣言の記法を決める）の材料を出すためのもの。

> ディレクトリ構造からのドメイン推定は、どんな置き方で外れ、判定をどう変えるか。

## 使い方

```bash
pnpm install --frozen-lockfile   # typescript-language-server を入れる（CI と同じ）
bash harness/domain-probe/probe.sh tests/layouts/layered
```

対象は `src/`（走査の根）と `domains.tsv`（正解のドメイン）を持つディレクトリ。
書式は `tests/layouts/README.md`。

## 何を数えるか

`scan --format json --explain` の候補ペアごとに、ディレクトリを見ている 3 つのシグナルを
正解のドメインと突き合わせる。

| シグナル | 今の推定 | 正解で置き換えた形 |
|---|---|---|
| モジュール距離 | 2 段以上離れていれば別ドメイン側 | 正解のドメインが同じなら共通化する側、違えば共通化しない側 |
| 呼び出し元ドメイン | 参照元ファイルの**すぐ上のディレクトリ**で数える | 参照元のディレクトリを正解のドメインへ引き直して数える |
| 呼び出し先ドメイン | 呼び出し先ファイルの**すぐ上のディレクトリ**で数える | 呼び出し先のディレクトリを正解のドメインへ引き直して数える |

そのうえで、**置き換えた傾きで判定を出し直し、ラベルが変わったペア**を数える。

## 宣言の実装を確かめる（Issue #237）

置き方のディレクトリに `dryguard.toml`（`[domains]` の宣言）があれば、そのディレクトリから
宣言付きで `scan` を走らせ、**正解で出し直した判定と候補ペアごとに突き合わせる**。
1 件でも食い違えば終了コード 1 で止まる。

- 突き合わせるのは、呼び出し元・呼び出し先を正解へ引き直せたペアだけ（下の「限界」）。
  引き直せなかったペアは、宣言で走らせた判定と並べて出すだけにする
- 宣言は `domains.tsv` の正解をファイル単位の glob で書いたもの。**関数単位の正解を持つ
  `grab-bag/` には置いていない**（宣言は関数単位を持たない。Issue #36 の決定）

## 限界

- **呼び出し元・呼び出し先はディレクトリでしか引き直せない。** `scan` の出力は参照元・
  呼び出し先をディレクトリごとに数えたもので、ファイルまでは出さない。1 つのディレクトリに
  別々のドメインのファイルが同居している（`layered/` の `services/` など）と引き直せないので、
  その観測は「測れない」として出し直す（`mixed-directory` と出る）。宣言付きの `scan` は
  ファイル単位で引けるので、そうしたペアは突き合わせの対象から外す
- **決定木は `src/classification.rs` の写し。** ずれていないことを毎回確かめる —
  推定のままの傾きで出し直した判定が `scan` の判定とすべてのペアで一致しなければ止まる
- 頻度の証拠にはならない（`tests/layouts/README.md`）

## なぜプロダクトの外にあるか

`domains.tsv` は記法を決めた材料で、宣言（ファイル単位）より細かい関数単位の正解まで持つ。
ここは記法を決めるための調査と、その実装を正解で確かめる足場で、LSP を要するうえ落ちたら
CI が止まる検査には混ぜない（`harness/phase0/README.md`「なぜプロダクトの外にあるか」と同じ判断）。
