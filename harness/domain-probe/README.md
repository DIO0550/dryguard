# ドメイン推定の外れ方を数える足場

Issue #36（`dryguard.toml` でのドメイン宣言の記法を決める）の材料を出すためのもの。

> ディレクトリ構造からのドメイン推定は、どんな置き方で外れ、判定をどう変えるか。

## 使い方

```bash
pnpm install --frozen-lockfile   # typescript-language-server を入れる（CI と同じ）
bash harness/domain-probe/probe.sh tests/layouts/layered
```

対象は `src/`（走査の根）と `domains.tsv`（正解のドメイン）を持つディレクトリ。
書式は `tests/layouts/README.md`。

## 何を数えるか

`scan --format json --explain` の候補ペアごとに、ディレクトリを見ている 2 つのシグナルを
正解のドメインと突き合わせる。

| シグナル | 今の推定 | 正解で置き換えた形 |
|---|---|---|
| モジュール距離 | 2 段以上離れていれば別ドメイン側 | 正解のドメインが同じなら共通化する側、違えば共通化しない側 |
| 呼び出し元ドメイン | 参照元ファイルの**すぐ上のディレクトリ**で数える | 参照元のディレクトリを正解のドメインへ引き直して数える |

そのうえで、**置き換えた傾きで判定を出し直し、ラベルが変わったペア**を数える。

## 限界

- **呼び出し元はディレクトリでしか引き直せない。** `scan` の出力は参照元をディレクトリごとに
  数えたもので、ファイルまでは出さない。1 つのディレクトリに別々のドメインのファイルが
  同居している（`layered/` の `services/` など）と引き直せないので、その呼び出し元は
  「測れない」として出し直す（`mixed-directory` と出る）。**宣言を実装すればファイル単位で
  引けるので、そこで変わるラベルはここの数より多くなりうる**
- **決定木は `src/classification.rs` の写し。** ずれていないことを毎回確かめる —
  推定のままの傾きで出し直した判定が `scan` の判定とすべてのペアで一致しなければ止まる
- 頻度の証拠にはならない（`tests/layouts/README.md`）

## なぜプロダクトの外にあるか

`domains.tsv` を `dryguard.toml` に読み込む形にすると、Issue #36 が決めようとしている
粒度と優先順位を先取りすることになる。ここは記法を決めるための調査で、落ちたら CI が
止まる検査には混ぜない（`harness/phase0/README.md`「なぜプロダクトの外にあるか」と同じ判断）。
