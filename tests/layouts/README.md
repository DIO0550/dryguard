# tests/layouts — ディレクトリとドメインが食い違う置き方のコーパス

`harness/domain-probe/probe.sh` を当てる対象。**ディレクトリ構造からのドメイン推定が
どこで外れ、判定をどう変えるか**を見るために置いてある（Issue #36「ドメイン宣言の記法を決める」）。

| 置き方 | 形 | ファイル数 |
|---|---|---|
| `nested/` | 機能の中がさらにネストしている（`billing/invoices/…` と `billing/payments/…`） | 13 |
| `layered/` | 層で分けている（`controllers/` `services/` `repositories/` `models/` の下に、請求と在庫が並ぶ） | 8 |
| `grab-bag/` | 何でも入れる `utils/` に、別々の機能の処理が 1 つのファイルで同居している | 6 |

どれも `src/` が走査の根で、`tsconfig.json` を置いてある（呼び出し元ドメインを測るには、
ファイルが `project marker` の下にある必要がある）。

## `domains.tsv` が正解のドメイン

各置き方の `domains.tsv` に、**どのファイル（または関数）がどの機能に属するか**を書いてある。
`probe.sh` はこれを正解として、推定が外れたかを数える。

| 列 | 中身 |
|---|---|
| 1 | `src/` からの相対パス。`/` で終われば、その下のファイルすべて |
| 2 | `*`（ファイル全体）か関数名。関数名で書いた行はファイル全体の行より優先する |
| 3 | 正解のドメイン |

**これはドメイン宣言の記法ではない。** 記法を決めるための材料で、関数単位まで書けるのは
`grab-bag/` の同居を正解として書き表すため。`dryguard.toml` に何を書かせるかは Issue #36 で
決めた（パスの glob。ファイル単位まで）。

## `dryguard.toml` は正解を宣言で書いたもの

`layered/` と `nested/` には、`domains.tsv` の正解を `[domains]` の glob で書いた
`dryguard.toml` を置いてある。`probe.sh` はこれがある置き方で、**宣言付きの `scan` が
正解で出し直した判定と一致するか**を突き合わせる（Issue #237）。

`grab-bag/` には置かない。正解が関数単位（`utils/helpers.ts` の中の同居）で、ファイル単位の
宣言では書き表せない。

`domains.tsv` を直したら `dryguard.toml` も直す。**片方だけ直すと、突き合わせが
正解の食い違いを宣言の実装の誤りとして報告する**。

## `tests/corpus` と何が違うか

**問いが違う。** `tests/corpus/` は `billing/` `inventory/` のようにディレクトリ 1 つ = ドメイン 1 つで
書いてあり、判定の傾向を見るためのもの。ここは**その前提が崩れる置き方**だけを集めてある。

`tests/scan.rs` が `tests/corpus/` 全体の数（関数・ペア・候補）を固定しているので、
置き方の実験をあちらに足すと閾値の母数が動く。それを避けるためにも分けてある。

## それでも頻度の証拠にはならない

**どの置き方を何件書くかをこちらで決めている。** 「推定が外れたときに判定がどう変わるか」は
言えるが、「実際のコードベースでそれがどのくらい起きるか」は言えない（`tests/corpus/README.md`
「それでも頻度の証拠にはならない」と同じ理由）。頻度は、判定のことを考えずに書かれた実コードで
測る（Issue #88）。

## 書くときの約束

- **判定を先に決めない。** 置き方だけを決め、中身はその機能に必要な処理として書く
- **推定を外すための細工をしない。** 置き方そのもの以外で外れやすくすると、外れた数がこちらの
  書き方の数になる
- `domains.tsv` を直さずに関数を足さない。`probe.sh` は表に無いファイル・関数で止まる

## ビルドしない

`compare` / `scan` に読ませる入力で、動かすアプリケーションではない。ただし
**型としては通るようにしてある**（`node_modules/.bin/tsc -p tests/layouts/<置き方>/src` が通る）。
呼び出し元は references で数えるので、解決できない参照を書くとシグナルのほうが壊れる。
