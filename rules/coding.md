# コーディング規約

**前提**: 所有権・借用・`Result` / `?`・命名など**言語共通の Rust 規約は d-market-rust の
`coding-standards` スキルが持つ**。ここに書くのは、それに足す・逸脱する分だけ
（`AGENTS.md`「規約の持ち場」）。

## 前提として守るもの（プラグイン側の再掲はしない）

- 早期 return でネストを浅くする
- `cargo clippy --all-targets -- -D warnings` の警告をすべて解消する
- マジックナンバーは定数化する
- 参照を優先し、変更が要るときだけ `&mut`
- `let` を基本にし、`mut` は必要な場合のみ
- 失敗は `Result`、伝播は `?`

## エラーと不在の表現

### `unwrap()` / `expect()` は本番コードで使わない

**この禁止はツールが落とす。** `Cargo.toml` の `[lints.clippy]` が `unwrap_used` /
`expect_used` を `deny` にし、`clippy.toml` の `allow-unwrap-in-tests` /
`allow-expect-in-tests` がテスト内だけ許可する。

**Why**: 「規約に書いてある」だけでは、読まれなかった回に通ってしまう。
ツールで落とせるものは規約の文に留めない（`.claude/hooks/README.md`「強制力の序列」）。

### 不在は `Option`、失敗は `Result`

- 「見つからない」「まだ取れていない」は `Option`
- 「やってみたが駄目だった」で、**呼び出し側が理由で分岐しうる**なら `Result`
- **失敗を握りつぶして既定値へフォールバックしない。** 呼び出し側が分岐できるよう、そのまま伝播させる

`LocationParseError` が `NotANumber` と `ZeroLine` を分けているのがこの形。
どちらも「行番号が駄目」だが、**利用者が直す先が違う**ので 1 つにまとめない。

### エラー型は原因ごとにバリアントを分ける

`String` 1 本のエラーにしない。**呼び出し側が分岐できる粒度**でバリアントを切り、
`Display` で人が読む文にする。バリアントが持つ値は「読めなかった文字列」など
**直すために要る情報**に限る。

## 生成時に検証し、不正な値を存在させない

制約を持つ値は、**生成する関数が検証込みで作る**（Smart Constructor）。
検証に失敗しうるなら `Option` / `Result` を返し、「生成された = 制約を満たしている」を成立させる。
生成後に呼び出し側が検証する設計にしない（検証を通っていない値が型上は同じ顔で流通する）。

```rust
// OK: 範囲外・NaN では作れない。作れた時点で 0.0-1.0 が保証される
impl Threshold {
    pub fn new(value: f64) -> Option<Self> {
        if value.is_nan() || !(0.0..=1.0).contains(&value) {
            return None;
        }
        Some(Self(value))
    }
}
```

- **標準の型で表現できるならそれを使う。** 行番号は「0 が存在しない」ので
  `NonZeroUsize`（自前のラッパを作る前に標準を探す）
- **型が構造で狭まっているかを確かめる。** `type Score = f64;` のような別名は
  素の `f64` がそのまま代入できるので、**何も防いでいない**

## 値の語彙を型で閉じる

取りうる値が仕様上決まっているものを `String` / `f64` のままにしない。

このツールが扱う語彙はほぼ決まっている。**enum にする。**

| 語彙 | 型 |
|---|---|
| 判定ラベル | `enum Verdict { ExtractCandidate, DoNotExtract, Review }` |
| 対象言語 | `enum Language { .. }` |
| 出力形式 | `enum OutputFormat { .. }` |

- **スコアと閾値を素の `f64` で混ぜない。** 取り違えても型エラーにならない
- **まだ動かない選択肢を enum に並べない。** `OutputFormat::Json` を先に足すと、
  選べるのに何も変わらない値がヘルプに出る。**使う側は「指定が効いていない」と
  「未対応」を区別できない**

## 不正な状態を型で表現できなくする

矛盾した状態が作れてしまうなら、取りうる状態を**判別可能な enum で列挙**する。

```rust
// NG: 「取れていないのにスコアがある」「取れたのにスコアが無い」が表現できる
struct Signal { available: bool, score: f64 }

// OK: スコアを持つのは取れたときだけ、が構造に出る
enum Signal {
    Unavailable { reason: UnavailableReason },
    Measured { score: Similarity },
}
```

`match` は `_` の受け皿を置かずに書く。バリアントを足したときに**黙って既存の枝へ落ちない**
（コンパイルエラーになる）。網羅のためだけの `_ => unreachable!()` は書かない。

## コメントは doc と Why / Why not に絞る

書いてよいのは次の 3 つだけ。**それ以外は消す。**

1. **doc** — その関数・型・定数が何か、引数、戻り値、失敗の条件
2. **Why** — なぜその形にしたか
3. **Why not** — なぜ他の選択肢を採らなかったか

### doc に書く項目

Rust の慣習に従い、rustdoc の書式で書く（JSDoc の `@param` は使わない）。

| 持っているもの | 書くこと |
|---|---|
| 引数 | その引数が何を表すか。**型の再掲は書かない** |
| 戻り値 | 何を返すか。`Option` / `Result` なら**どんなときに `None` / `Err` になるか** |
| `Result` を返す | `# Errors` セクション |
| パニックしうる | `# Panics` セクション |

### Why と Why not は別物として書く

Why だけだと「他にどんな道があったか」が残らず、次に読む人が同じ検討をやり直す。

```rust
// 右から分割する。左からだと Windows のドライブレター (`C:\a.rs:12`) を
// 区切りと取り違える。
let (path, line) = text.rsplit_once(':')...
```

- **Why not を書く相手は、実際に検討して捨てた案だけ。** 思いつく限りの代案を並べない（それは Issue の担当）
- Why / Why not は **1 つにつき 1〜2 行**に収める。3 行以上要るなら Issue に書くべき経緯が紛れ込んでいる

### 消すもの

| 消すもの | 理由 |
|---|---|
| What の言い換え | コードが既に言っている |
| コード内の値の再掲 | 二重管理になり、片方だけ直ると食い違う |
| 経緯・実行履歴 | Issue / PR の担当 |
| Issue の番号だけを指すコメント | コードだけを読む人に何も伝わらない。理由そのものをその場に書く |
| 一般論 | この箇所固有の情報ではない |

**判断軸は「これを消したら、次に読む人が同じ間違いをするか」。** しないなら消す。

## 禁止事項

- **lint 抑制を足さない**（`#[allow(..)]` / `#[expect(..)]`）。
  抑制したくなったら**設計のほうを変える**（`dead_code` が出たので lib + bin に分けた、が実例）
- `unsafe`
- `stage1` / `stage3` での I/O（ファイル読み込み・プロセス起動）。I/O は `lsp` と入口の層のみ
